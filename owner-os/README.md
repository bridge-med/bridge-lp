# OWNER OS(仮称)

現場で手を動かす側から、任せる側(プロジェクト責任者)になった人のための、意思決定・委任支援ツール。

BRIDGEの型(評価 → 理解 → 設計 → 実践 → 再評価)のうち、**設計と実践**を支える道具です。
増やしたい選択肢は「抱え込む以外のやり方」——決める・聞く・任せる・意図して保留する、の4つです。

一般的なタスク管理と違い、管理する対象は「作業」ではなく次のものです。

- 今、誰がボールを持っているか
- 自分が決めるべきことは何か
- 誰かに聞く・任せるべきことは何か
- 誰の回答待ちで、いつ催促するか
- プロジェクトを止めているものは何か

「責任を持つこと」と「自分ですべて実行すること」は違う——この前提で、
タスクを受けたらまず「自分で決める・誰かに聞く・誰かに任せる・今はやらない」の
4分類へ誘導する設計になっています。

## 起動方法

ビルドは不要です。リポジトリのルートで静的サーバーを立てて開きます。

```bash
# 例1: Python
python3 -m http.server 8000
# → http://localhost:8000/owner-os/

# 例2: Node
npx serve .
```

初回起動時に名前を入れると、サンプルデータ(医療法人統合プロジェクト)が
入った状態で始まります。データはブラウザの localStorage にのみ保存され、
外部には送信されません。

## 画面

| 画面 | 内容 |
|---|---|
| はじめる(ログイン) | 名前を入れて開始。登録・パスワード不要 |
| ダッシュボード | 今日の4区分(決める・渡す・催促する・止まっているところ)+停滞シグナル |
| タスク一覧 | ボールの所在を先頭に置いた一覧。状態・プロジェクトで絞り込み |
| タスク登録 | 3段階ウィザード(内容 → 4分類 → 担当と期限) |
| タスク詳細 | ボール移動・依頼文/質問文/催促文の下書き・履歴 |
| プロジェクト一覧/詳細 | 停滞警告+ボール別ボード |
| 関係者 | 誰にどれだけ渡しているか(集中の検知つき) |
| リフレクション | 感情まじりの入力を「事実・解釈・感情・課題・次の行動・再発防止」に分解 |
| 週次レビュー | 意思決定・委任・催促の傾向と停滞の振り返り |
| 設定 | 名前変更・データ書き出し・全削除 |

## 構成

```
owner-os/
├── index.html        # アプリ本体の入口
├── app/
│   ├── store.js      # データモデル・localStorage永続化・停滞検知・週次集計
│   ├── ai.js         # 「次の一手」下書きのサービス層(既定はルールベース)
│   ├── app.js        # 画面描画とイベント処理
│   └── styles.css    # トークンベースのスタイル(ライト/ダーク対応)
└── test/
    └── store.test.mjs
```

## 文章の下書き(AI相当機能)について

分類候補・依頼文・催促文・リフレクションの分解は、現在は **端末内の
ルールベース** で生成しています(外部送信なし)。UI では「AIの提案」では
なく「下書き」と表現しています。

外部API(Anthropic / OpenAI)へ差し替える場合は `app/ai.js` の
`providers.anthropic` / `providers.openai` に実装を足します。UI側の変更は
不要です。ブラウザから直接APIを呼ぶとキーが露出するため、実運用では
中継サーバーを挟んでください。

## テスト

```bash
node --test owner-os/test/store.test.mjs
```

データ層(store.js)と下書き生成(ai.js)のロジックを検証します。
サイト全体の機械検査は従来どおり `node scripts/check-site.mjs`。
