# THE FUTURE OF CLINIC OPERATIONS

約23秒のモーショングラフィック作品(1920×1080・60fps・無音)。クリニックの散らばった数字がつながり、判断の材料が浮かび、人が選んだことが画面に残り、先の日々まで見渡せるようになるまでを、切らずに1カットのカメラで描く。

数値と名称はすべて架空のサンプル(整形外科とリハビリテーション科の外来を想定した一日の模擬)。実在の医療機関・製品・人物とは関係がない。

## 見る

- マージ後: https://bridge-med.github.io/bridge-lp/clinic-ops-motion/ (noindex。どこからもリンクしていない)
- 手元: リポジトリのルートで `python3 -m http.server 8000` → http://localhost:8000/clinic-ops-motion/ (`index.html` を直接開いても動く。書体は Google Fonts から読むので回線が要る)
- 確認用: `?t=12.5` でその時刻に止めて開く
- 操作: 再生/一時停止(Space・K・映像をクリック)、最初から(Home)、シーク(スライダー・← →で1秒、Shift+← →で1コマ)、場面へ移動(スライダーの下の章)、全画面(F。使えない端末ではボタンを出さない)
- 動きを減らす設定では自動再生せず、最後の1コマと再生ボタンを出す

## MP4 に書き出す

ブラウザで描くのと同じコードを1コマずつ描き、ffmpeg で H.264 にする。書き出しの道具は `showreel/render.mjs` を書き換えずに使う(この作品は `?render=1` で `window.REEL` を持つ)。

```
node showreel/render.mjs --page clinic-ops-motion/index.html --out clinic-ops-motion/film.mp4 --crf 22
```

- 依存: playwright(chromium)と ffmpeg。Google Fonts の要求は curl のキャッシュから返る(render.mjs の既定)
- 動きのぼけ: シャッター 180°。1コマのあいだに画面上で動く距離からサブフレームの数(1〜24)を決め、浮動小数で平均する。粒子は平均のあとに1回だけ掛ける
- 静止画だけ: `--stills 3.2,16.8,22.9 --outdir <dir>`

## 前提(design-system §5)

1. 誰が・何を: 院長・事務長・運営担当(と経営支援に関わる人)が、受付から会計までの数字がつながると何を選び直せるか(待ち時間のピーク、リハ室の空き)を約23秒で体感する映像作品。第10条の型の「評価→理解」の段。道具ではないので PRODUCTS に載せない(第31条の申告)
2. どこで: PC の全画面と、プレゼンの大画面(投影機では黒が浮く)が主。音なしで成立させる(自動再生は無音)。スマホは横長の窓か、共有した 1080p の MP4
3. どんな体験: 散らばった数字の中で迷う感覚 → つながって構造が見える安堵 → 判断の材料が浮かぶ瞬間 → 人が扱える画面に落ち着く確かさ → 先の日々まで見渡せる静かな高揚。止めずに見ても、読ませる拍で筋が追える
4. 比べた方向: FOCAL(光学・計測機器から)/ Daylight Ledger(編集・印刷物から)/ Living Model(建築・シミュレーションから)
5. 選んだ方向と理由: FOCAL。ピントが合うことがそのまま SEE CLEARLY になり、奥行き・カメラ・光を物語の手段で満たす。出発点がブランドの面とも clinic-flow-3d とも違う(designer 推奨 2026-10-18)

## 面と、及ぶ規定

- 面: プロダクトの画面(作品)。BRIDGE が自分の名で語る映像ではない(憲法第30条の2第1号)。`showreel/` `film/`(ブランドの面)には置かない。映像のコマの中に BRIDGE の名・マークを置かない。BRIDGE との接点は再生ページの文字リンク(公式サイトへ)だけ
- 及ぶ: 第1〜5章・第8〜9章、第7章の趣旨(行き止まりを作らない・押し付けない など)、design-system §5 の共通の品質基準、context.md 冒頭の「前提にかかわらず共通に守る」項
- 及ばない: 第6章(色・書体・署名)の全体、第7章の形、design-system §1〜§4・§6。`shared/bridge.css` は読まない

### 制作中に当たったこと(当たったその場で書いた)

- 置き場所を `showreel/` にすると、§0 によりブランドの面(BRIDGE 自身の映像)になり、藍と砂・明朝・交差が及ぶ。独立した作品としたので新しいディレクトリに置いた。分類の根拠は §0 の一覧ではなく第30条の2第1号の定義(PM)
- 「改善の見込み(試算)」を見せる案は、架空の値には試算の根拠がないため外した(第15条。PM)。判断の場面は、材料に括弧を付けるところまでを画にし、選ぶのは人にした(第9条2号。designer)
- 架空の注記は、どのコマを切り出しても残るように全コマに焼き込み、320px では読めないのでページにも同じ文を置いた(第13条)
- 光は焦点の文法(ぼけ・ピント送り・絞り)に限り、にじみは明るい点に薄く掛けるだけにした(designer)。暗い場のテック映像の定型に寄せないため
- 読ませる拍(冒頭の一文・一日の図・ピークと空き・選択肢・昼の画面・締め)ではカメラをほぼ止めた(designer)
- 昼の配色で、琥珀と氷の青は1つの値では AA を満たせない。小さな文字には別の値(`--d-amber-ink` `--d-ice-ink`)を使った(designer)
- canvas の `filter`(ぼけ)は Safari で効かないことがある。起動時に一度確かめ、効かなければ縮小と拡大でぼかす(designer)
- 点滅: レンズのそばを通るぼけの円は近づくほど暗く薄くして消し、夜から昼への反転は1回だけにした(WCAG 2.3.1)
- 書き出しの道具は新しく作らず `showreel/render.mjs` を使った。ブラウザ内での MP4 書き出しは、同じ映像を出す2本目の経路と依存が増えるので作らなかった(§5 保守性。PM)
- 締めの言葉は、依頼の例「SEE CLEARLY. DECIDE BETTER.」から「SEE CLEARLY. THEN DECIDE.」に変えた。この作品は効果も答えも描かない設計で、最後の BETTER だけが良し悪しを断定し、見る人に「もっと良く決めよ」と迫る形になるため(第9条2号・第15条の趣旨。editor)。英字の文末のピリオドは第19条5号の句点(。)に当たらない(先例 EXPAND CHOICES.)。ピリオドにだけ色を付けることはしない
- 人が選ぶのは3つのうち2つ目にした。1つ目を選ぶと「並びの先頭=おすすめを受け入れた」と読まれる余地があるため(editor)
- 5秒を超える自動再生は止められるようにした。作品の時間そのものは §5 の「動きを減らす設定」の除外に当たるが、冒頭の速い前進を考えて、その設定では自動再生しない

## デザイン: FOCAL

見えないものにピントが合っていく過程を、そのまま物語にする。光学(ピント・絞り・オートフォーカス)を、作品の視覚の文法にした。

- **ピント** — 冒頭は被写界深度の浅いレンズで、数字の粒の多くがぼけている。「THE PICTURE ISN'T.」はわざとぼけたまま置く。横に走る焦点の線が通ったところからピントが合い(ラックフォーカス)、締めの言葉も、ぼけた字にピントが合って立つ
- **角の括弧(AF ブラケット)** — 枠は箱ではなく四隅の括弧で示す。焦点が合った断片、待ちのピークとリハ室の空き、ダッシュボードの部品が、括弧が外から締まって「止まる」。カードを並べてフェードインさせる見せ方を使わない
- **絞りの輪** — 人が選んだ点から目盛りつきの円が開き、夜の配色が昼に一度だけ反転する。見えなかったものが、人の扱える画面になる瞬間
- **1カット** — 断片が降りた平面が、そのまま図になり、ダッシュボードになり、床に倒れて先の日々のタイルの中の「今日」になる。カメラは突入・旋回・ドリーズーム・引き・クレーンで構図を変え、切らない

### 色(値は `index.html` の `:root` だけに置き、描画のコードもそこから読む)

| 役割 | 夜(CHAOS〜INTELLIGENCE) | 昼(CONTROL〜FUTURE) |
|---|---|---|
| 地 | `--n-bg` #04070A(墨に近い青黒) | `--d-bg` #E7ECEF(冷たい白)、板 `--d-panel` #FFFFFF |
| 文字 | `--n-ink` #E8EFF4 / `--n-ink-2` #A6B7C4 | `--d-ink` #0B1218 / `--d-ink-2` #46535E |
| 流れ(患者の動き・熱) | `--n-ice` #8ACBF2 | `--d-ice` #4C93C9(文字は `--d-ice-ink` #1F5F92) |
| 注意を向ける点だけ | `--n-amber` #FFB547 | `--d-amber` #EE9512(文字は `--d-amber-ink` #8F4E00) |

琥珀は「いま」の線・材料の括弧・選んだ選択肢・満ちた日・今日の縁にだけ使う。装飾に使わない。色はこの4系統で足りる。

### 書体

- Archivo(Expanded 600/700) — 英語の大きな文字。幅の広いグロテスクで、計測機器の刻印のような静かな強さ
- Chivo Mono(300〜500) — 数字と時刻。等幅なので数が増えても桁が揺れない。Archivo と同じ書体の系統(Omnibus-Type)
- Zen Kaku Gothic New(500/700) — 和文のラベル。小さくても読める、硬すぎないゴシック

### 動き

- 緩急は数本だけ(`js/core.js` の `ease`)。標準の移動 cubic-bezier(.65,0,.35,1)、着地 (.16,1,.3,1)、ピント送り (.8,0,.12,1)、冒頭の前進 (.25,.9,.3,1)
- カメラの値は「基準+差分×緩急」の重ね合わせで書き、区間が重なるところで動きがつながる。ほぼ止まる拍でも、ごく小さな手持ちの揺れを残す
- 書き出しでは動きのぼけ(シャッター 180°)。実時間の再生では、冒頭の速い前進のときだけ粒に短い尾を引く

## 実装

- 静的なページ。ビルドなし、外部のライブラリなし(書体だけ Google Fonts)
- `index.html` — 再生ページと色・書体のトークン(`:root`)
- `js/core.js` 数・緩急・決定的な乱数・色の読み込み / `js/engine.js` カメラ・投影・被写界深度(ぼけの段を持つスプライト)・平面への描画・仕上げ(にじみ・周辺減光・粒子) / `js/data.js` 架空のクリニックの一日の模擬 / `js/film.js` 5つの場面とカメラの台本 / `js/player.js` 再生・操作・書き出し用の `window.REEL`
- 1枚は時刻 t だけで決まる(乱数は種から決まる)。シーク・一時停止・書き出しが同じ絵になる
- 数字は模擬から計算する(来院 81・平均待ち 24分・10時台 37分・リハ室の空き 36%・次の来院 14:34・次の枠 14:40・稼働率 73%・職員の負荷)。患者単価 ¥5,860 と来週の予約、先の日々の見込みは架空の値を置いた
- 重い端末では、解像度 → 粒子 → にじみ → 粒の数 の順に段を下げる(描画が 20ms を超え続けたとき)

## 計測

GPU のない検証環境(コンテナの headless Chromium、ソフトウェアで描画)での値。実機の値ではない。

| 条件 | 描画 1 回(p50 / p95) | コマの間隔(p50 / p95) | 画質の段 |
|---|---|---|---|
| PC 相当 1440×900・canvas 1337×752 | 6.7ms / 17.8ms | 33ms / 50ms | 0(全部) |
| スマホ相当 390×844・DPR3・CPU 4倍遅く | 10.6ms / 33.9ms | 33ms / 83ms | 3(最も軽い) |

- この環境ではコマの間隔が描画ではなく画面への出力で決まり、約30fpsで頭打ちになる。描画そのものは PC 相当で 1 コマ 16.7ms にほぼ収まる
- 実機(GPU のある PC・スマホ)での fps と落ちたコマは未確認
