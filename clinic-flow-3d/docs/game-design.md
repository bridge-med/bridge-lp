# ゲームデザイン(v33時点の到達点と方針)

## 中心思想

患者が医療を受ける → 診療行為が発生 → **診療報酬エンジンが算定を判定** → 売上になる →
施設基準・人員・設備・経営判断で収益構造が変わる。診療報酬は固定単価ではなくルールそのもの。

## 遊びの柱(v32から継承)

外来経営シム(実点数の学び) × 3D視察(院内⇄街) × 人格(ペルソナ・常連) × 継続導線(デイリー・実績・リーグ)

## 経営モード / 学習モード

- 経営モード(既定): レシートは項目と点数のみ。KPI・待ち時間・負荷中心の簡潔表示
- 学習モード(レシートの🎓ボタン): 算定詳細を常時展開 — なぜ算定できたか(条文引用+出典)、
  なぜ算定できなかったか(理由+条文)、未取得施設基準の増収余地
- `?debug=1` でReimbursement Debugger(評価トレース)を算定詳細に表示

## 4つの経営スコアへの道筋(未実装・方針)

現状は 経営(利益・キャッシュ)・患者(待ち・満足度)・組織(スタッフ負荷・絆) が実装済み、
医療(適切な算定・needs_reviewの解消率)は学習モードの土台の上に次段で載せる。
一つの軸の最大化が他を悪化させる設計(待ち時間×回転×単価のトレードオフ)は既に機能している。

## 時間システム

日次(診療・会計) → 月次(レセプト集計・月次決算) → 年次(リーグ)。実装済み。

## 診療報酬改定イベント(方針)

KBパックは revision 単位(kb-r08.js)。令和10年度はパック追加+切替UI(価格・施設基準・
算定条件が変わる経営イベント)として実装する。ゲーム内の`G.kaitei`イベント基盤と接続予定。

## 制度とゲームの分離(憲章)

- 制度上の事実: KB由来のみ。出典を常に表示できる
- ゲーム上の仮定: 需要・確率・人件費・採用費・営業成功率・簡略化した届出タイミング。
  UI上で「概算」「ゲーム上の簡略化」「simulation estimate」と明示する
- 制度的に不自然な誘導をしない(過剰診療をゲームが推奨しない。診療方針スライダーは
  「医学的必要性が前提」の注記付き。連携は患者ニーズに基づくものとして扱う)
