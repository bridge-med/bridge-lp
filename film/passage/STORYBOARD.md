# PASSAGE(仮題)— 絵コンテとキュー表

15秒のブランド映像。空間に入っていき、プロダクトが次々に現れる。
「一本の線」(PR #131)とは別の映像として作る。あちらは平面の上で読み、理解する映像。

- 形式: 15.000 秒・1920×1080・60fps(縦 1080×1920 は同じ世界から撮り直す。未着手)
- 使い道: X・note の投稿。LP トップに置くかは未定(置くなら ia.md の改定が要る)
- 無音の自動再生で成り立つように作る。音は後から足す
- この文書は制作の記録。公開ページからはリンクしない

## 1. 完成イメージ

白い建築模型のような空間を、カメラが止まらずに通り抜ける。

- 部屋は、個人の部屋 → チームの部屋 → 組織の広間 と大きくなる
- 部屋には独立した壁(バッフル)が1枚ずつ立ち、実在の道具の画面(写し)が1枚ずつはまっている
- 壁の両脇はどちらも通れる。カメラは片方を選び、もう片方の道も奥へ続いている
- 最後の広間で、カメラは横へ滑りながら一点に着く
  - 柱や壁に散って塗られていた藍の断片が、一本の弧に揃う
  - 手前に固定された砂の板が、その弧と交差してロゴになる
- 藍と砂は奥行きが違い、交わって見えても離れている
- 動くのはカメラだけ。建築・写し・藍・砂は、最初から同じ場所にある

## 3. シーンごとの目的

- **S1(0〜3秒)**:
  - タイムラインで指を止める
  - 1フレーム目に三つを入れる: 手前の枠、暗い画面(白い部屋との図と地)、問い
  - 問いは見る人に向ける。読んだ人が、自分の答えを一瞬思い浮かべるように
  - 2026-09-27 の試験: 横 360px に縮めて低いビットレートで再圧縮すると、暗い画面の図と地は残るが、問いの文字は読めない(字の高さ約3px)。問いが読めるのは全画面で見たときだけ。フィードでの手当ては判断待ち(縦版で大きく撮る など)
- **S2〜S7**:
  - 個人の道具からチームの道具へ、部屋が大きくなる(個人 → チーム → 組織。社会の部屋はまだない)
  - 対象は患者に限らない(第4条)
  - 間隔は揃えない(第19条2号: 三連の等拍にしない)
- **S4**:
  - 分かれ道を建築で見せる(第24条の補助モチーフ「分岐する道」を立体で)
  - 一本道にしない(第26条・第9条2号)
  - 現状は、敷居の二つの口が同じコマに入る時間がない(designer の指摘。次の段で直す)
- **S8〜S9**:
  - 門で狭まり、広間で開ける(圧縮 → 開放)
  - 藍の断片はここで初めて見える
- **S10**:
  - 一つの構造だったことを、文字なしで見せる(`?copy=1` のときだけ和文の一文が重なる。判断待ち)
  - 揃う一点は、カメラが横へ滑って見つける
- **S11**:
  - 署名。コピーでマークの意味を決めない(第24条の2)

## 4. 規則

### カメラ
- 焦点距離は 28mm 相当(横の画角 65.5°)で固定する。ズームとドリーズームは使わない
- ロール 0°・ピッチ 0°。鉛直線を常に鉛直に保つ(建築写真の規律)
- 構図はレンズシフトで作る
  - 走行中は絵を画面の高さの 10% 上へずらして床を多めに入れる(白い壁だけのコマを減らすため)
  - 10.4〜12.2 秒で 0 に戻し、最終の視点では 0
- 目の高さは 1.4m
- ヨーの角速度は 60°/s 以下
- 速さは滑らかに変わる
  - 読ませる拍で落ち、角で上がる
  - 急な時間の伸縮(スピードランプ)は使わない
  - 止まるのは最後の一度だけ
- 手持ち風の揺れ・オーバーシュートは使わない
- 最後の保持は完全に静止させる(細い文字をサブピクセルで揺らさない)

### 画面の接続
- カットはない。一本の連続したショット
- 次の写しは、壁の陰から出て現れる。透明度で出し入れしない
- 読ませる写しは同時に1枚。境の壁が次の写しを隠す
- 実測(2026-09-27。0.25 秒ごとに、480px の画で2つ目の写しの画素を数えた割合)
  - 1.75 秒: 経験の棚卸しが 1.5%(Compass を読む拍の終わりに、奥の壁の右の口から見える)
  - ほかの時刻は 0。掲示じたくの拍に ConsultSim が見えていた件は、境の口を狭めて解消した
- 許容の案(designer): 2つ目が見えてよいのは切り替わりの合計 0.3 秒以内、画面の 3% 以下、2つ目の札は見せない
  - 決めるのは社長(第22条の写しの但し書きの解釈)
- 白い壁だけのコマを 0.1 秒以上続けない
  - 検査: 0.1 秒ごとの止め絵で、1色が画面の 80% を超えるコマを数える
  - 2026-09-27 時点で 0

### 写し(UI)の扱い(第22条の写しの但し書き)
- 実物のページから `capture.mjs` で撮る
  - 撮り直しで同じ画になるよう、入力は製品自身の入力例と固定の日付
  - 保存データなしの状態で撮る
  - 可逆の WebP で保存する(画素を変えない)
- 加工しない
  - 照明を当てない(`MeshBasicMaterial`・トーンマッピングなし)
  - 縦横比そのまま
  - 色補正・ぼかし・書き換え・合成をしない
  - 見せたくない部分は、撮る位置で枠の外に出す(掲示じたくの差出の行)
- 色を枠の外へ持ち出さない。床への映り込み・光のにじみを作らない
- 写しは壁の厚み(見込み 1M)の奥に納める。縁取りの線を足さない
- 名前の札の規則(全製品で同じ)
  - 開口の左端に揃え、腰の面に置く
  - 正式名称で書く(PRODUCTS の name)
  - Noto Sans JP 700 / Inter 500、色は --ink-2
  - 高さ 0.12m(写しの見出しより目立たない大きさ)
- 除外の基準
  - 実在の組織名、または姓と名がそろった実名風の人名が、読める大きさで写る写しは使わない
    - HireBoard: デモに実在の紹介会社名と実名風の人名が写る
    - StudyBoard: 運営者のメールアドレスが写っている
  - ゲームの中の役名(姓だけ)は可(クリニックタウン3D の「岡部」)
  - いまの製品と違う画面は使わない(クリニックタウン3D の旧画面)
  - 終わりのロゴの交差を先取りする図が主役の画面は使わない(職場モヤモヤ診断の×印)
    - Compass の写しの上端に写るサイトのナビのロゴ(幅約 27px)は、主役ではないので許容する
  - 数字は読める大きさ・長さにしない
    - ConsultSim の拍では数字が読める大きさにならない
    - クリニックタウン3D は、決定の窓を画面の中心に置き、上端の資金の欄を主役にしない
- 写しの一覧と撮影日は `plates/plates.json`
  - クリニックタウン3D だけは既存の公式の写し `images/products/shots/clinic-flow-3d-decision.webp`(2026-09-21 撮影・1440×900・1倍)

### 色(第22条)
- 使うのは `shared/bridge.css` のトークンの値だけ
  - 値は `passage.js` の `TOK` に一か所で書く
  - `render.mjs` が起動時に bridge.css の値と照合し、違えば止まる
- 面は、世界に固定した光の向き(左手前)で平塗りする
  - 床: --bg-2
  - 上向きの面(床以外): --bg
  - 光に向く鉛直面: --card
  - 光に背を向ける鉛直面: --bg-2
  - 下向きの面: --bg-3
- 面積の目安(BRIDGE が描く面。写しと文字を除く)
  - --bg・--card・--bg-2 の合計が 90% 以上
  - --bg-3 は 10% 以下
  - 藍は S10 まで 3% 以下
- 最終フレームの画素は、トークンの値(と文字の縁のなじみ)だけになっている(2026-09-27 に確認)
- 陰影・投影の影・AO・霧・グラデーション・グロー・ブルーム・粒子・グレイン・ビネットは使わない
- 藍(--navy)はロゴの断片だけに使う
- 砂(--dawn)は、画面が描くものとしてはロゴの砂の板の1か所だけ。写しの中の砂は数えない
- ガラスの青緑・夜の帯は使わない。映像のテーマはライトに固定(`render.mjs` は `--theme dark` を受け付けない)
- 明暗の混在: 白い建築の中に、ダーク表示の Compass の写しを1枚だけ置く
  - designer の判定は「可」
    - 暗いのは枠の内側だけで、製品の機能を選んだもの
    - ライト表示では、360px の縮小で画面がほぼ消える
  - ダークの写しはこの1枚だけにする(明暗が交互に来るリズムを作らない)

### 書体(第23条)
- 札: Noto Sans JP 700 / Inter 500
- 署名
  - BRIDGE: Inter 500・字間 0.34em・--ink
  - EXPAND CHOICES.: Inter 500・字間 0.22em・--ink-3・大きさは BRIDGE の 8.5/15
  - マークの下に BRIDGE と EXPAND CHOICES. を積む
    - マークが建築に固定されていて、横へ動かせないため
    - サイトの正式の組みは横組みなので、映像だけの組みとする(判断待ち)
    - マークと文字の間は、字高の 0.5 倍以上あける
- 900 は使わない
- 和文の一文を入れる場合は明朝 600(判断待ち。`?copy=1` で確認できる)

### 動き
- 動くのはカメラだけ
- 動きのぼけはシャッター 180°
  - サブフレームを線形光で平均する(`engine.js`)
  - サブフレームごとにサブピクセルずらして、線のジャギーと文字のちらつきを消す
  - 本番は 1コマ 12 サブフレーム。書き出しは 30〜40 分
- 点滅: どの1秒でも大面積の明暗の切り替えを3回以下にする(WCAG 2.3.1)
  - qa の確認版での測定は合格

### 藍の断片(Varini の方式)
- 最終の視点 V から見える面にだけ、正式の藍の線を塗る(V からの距離の地図で判定)
- 塗る先は、区間ごとに奥行きの違う柱(V から 6・9.6・11.5・15m)と奥の壁(25.6m)
- 柱の側面は V からの光線と平行に回してある
  - V からは正面だけが見える
  - 横へ滑る間は、陰の側面が断片の隣に見える
- 隣の区間と少し重ね、距離の比較は 3×3 の最大をとる(継ぎ目に塗り残しを出さない)

### 避ける表現
- 等間隔・同形の門が消失点へ続くトンネル(AE の 3D トンネル、千本鳥居)
- 白い無限スタジオでのロゴの組み上がり、浮遊する UI カード、無限ズーム、ミニチュアの街の空撮
- 光の筋・粒子・ネオン・レンズフレア・被写界深度のにじみ・色収差
- 医療の記号(聴診器・十字・病院の看板・白衣)
- 数を数える演出、実績の数字(第15条・2026-09-26 の社長指示)
- 「一本の線」の語彙
  - 線を引くペン
  - 線から浮く文字
  - 分岐の図・評価→再評価の5語
  - 横パン・引いて全体図
  - 線がロゴに曲がる終わり
  - ワードマークの字間が詰まる

## 5. 実装方式

**既存の HTML/Canvas の書き出し基盤を広げ、three.js で作る。Remotion は入れない。**

| 判断軸 | HTML + three.js(採用) | Remotion |
|---|---|---|
| 実装速度 | 描画器・書き出し・写しの撮影がすでに動いている | React・バンドラ・独自の Chrome の取得(この環境ではプロキシの証明書の問題で回避が要る)から始まる |
| 表現力 | three.js r128 の平塗りで十分に描ける。視点の一点で揃う塗り(距離の地図+シェーダ)と、線形光のぼけの蓄積も書ける | @remotion/three を使っても 3D の中身は同じ three.js。ぼけの蓄積は結局自前になる(同梱の動きのぼけは sRGB で平均する) |
| 保守性 | ビルドなし。サイトの家の規則(静的・ビルドなし・check-site)のまま | node_modules とバンドラに依存する最初のディレクトリになる |
| 既存資産の再利用 | 同梱の three.js(clinic-flow-3d/vendor)を使う。PR131 の書き出しの知見(bt709・フォントの取り方・ぼけの蓄積)も生きる | three を npm で別に持つことになる |
| 派生への展開 | URL の引数(縦横・和文の有無)で同じ世界から撮り直せる。縦版は鍵(`KEYS`)を縦用に持てばよい | 構成の管理は得意。ただし今回の派生は同じ3Dの撮り直しで、得意な場面ではない |

Remotion が勝つのは、DOM と字幕が主体の縦動画を量産する場面(プロダクト別の6秒版など)。そこで要るなら、改めて比べる。

## 付録: 検討した3案と選定

- **A「PASSAGE — 通り抜ける」**(採用)
  - 白い建築を一本のショットで通り抜ける
  - 写しは建築の開口にはまった場所として置く
  - 最後に視点の一点で藍の断片が揃い、ロゴになる
- **B「DIVE — 画面の奥へ」**
  - 画面の部品に潜ると次の道具が開く、入れ子の潜行
  - 写しの中に写しをはめ込むので第22条の加工に当たる
  - 無限ズームはテンプレ動画の定番で、空間もない
- **C「TOWN — 白い街を渡る」**
  - 白い模型の街を低空で渡る
  - ミニチュアの街の空撮はストック映像の定番
  - 街とクリニックの連想が病院に寄る(第21条)
  - モデリング量が最大

審査は、6つの役割を与えた AI のサブエージェントが別々に行い、6つとも A を選んだ。合計点は A 292.5・B 195・C 189。人の審査はまだ経ていない。
- designer
- pr
- editor
- pm
- 映像の批評(AI 臭さの検出)
- 実装の検証

骨格の照合(designer・editor・qa・映像の批評)も同じく AI のサブエージェントで行った。

A に取り込んだもの:
- C から: 分かれ道・規模の移り

- 実装の検証から: 浮動小数の蓄積・レンズシフトとずらしの合成・静止区間のディザの固定

  - 床を --bg-2 に
  - 冒頭の問いの差し替え(32字・選択済み → 12字・未選択)
  - 支えの柱の向き
  - マークと文字の間隔
