## 1. 読ませる文字の --ink-4(B-9)

**現物** 小さい文字は 4.5:1 が必要。残っているのは2つ。フッターの © と Privacy(bridge.js が描くフッター。`.site-footer` を置く11ページ)と、英字の副題16個(about `.tl-tag` 4・projects `.road-en` 6・philosophy `.tf-en` 6。3つとも `.sec.tint` の上)。どちらも地 `--bg-2` の上で 1.83(ライト)/ 2.49(ダーク)。`--ink-3` にすると 5.14 / 5.18。journal の日付と products の番号は、改修で `--ink-3` になり解消した。

**案** A: 2つとも `--ink-3` に上げる。B: フッターは `--ink-3` に上げ、英字の副題(Practice など)は削る。

**推奨 B** 英字の副題は日本語の題をなぞるだけで、新しい情報がない。足すより削るほうがよい(context.md §7「横文字を多用しない」)。対象は `--ink-4` の16個だけで、Projects の行の英字(`.row-t .en`・`--ink-3`)は含めない。

**決めてもらうこと** 英字の副題16個を消してよいか。

## 2. どの段にも入らない半径 9px(B-10)— 取り下げ

**現物** 改修(design-system v1.8)で journal の一覧が行型になり、9px は消えた。行の写し `.j-row .j-thumb` は 4px、実画面の写し `.lab-shot` は 3px で、どちらも Edge の段にある。ただし、先頭の一件の写し `.j-lead .j-thumb` が 8px で、どの段にも入らない(1か所)。§7 の B-10 は閉じたままになっている。

**推奨** 社長の判断は要らなくなった。前回の推奨 A(写しは Edge)は改修で実現している。残る 8px は §1「新しい半径を足さない」の範囲で、4px に直して B-10 の注記に足す(designer の領分)。

**決めてもらうこと** なし。

## 3. 第22条の3つを超える砂(B-12)

**現物** 台帳に載っているのは11種・8ファイルで、改修後も同じ。内訳は番号(projects 7・philosophy 5・services 3)、年(research 2)、英字ラベル(stories 6・community 4・ドロワー 全ページ 8)、道のりの最後の点(projects・services・philosophy)。about の「04 Now」の点は現在地なので、3つの範囲内。台帳にないものもある。見出しラベルの前の砂の短い線(`.eyebrow::before`)は10ページで37個あり、いちばん多い(services が Ask / Build に分かれて1個増えた。前回の35は Compass の1個を除いて数えていた)。このうち9個は Where to next のラベルで、分岐点の印とも読める。products の分類見出しの砂の線は、改修でなくなった。改修で、philosophy の核の一文の「選択肢を増やす」が砂になった(`.core .stmt .sand`。トップの `.idea-h .a` と同じ扱いで2か所目)。

**案** A: 3つに絞る。番号・年・英字ラベルは `--ink-3`、短い線は Where to next の9個だけ砂に残して残り28個を `--ink-4`(記号の役割)、最後の点は `--ink` にする。強調語の砂2か所は、句点と同じ「選ぶ瞬間の言葉」として残すかを同じ便で決める。B: 現状のままにして、「章の入口の印」を4つ目の用途とする憲法改定にかける。

**推奨 A** 砂がいちばん多く出るのは、選択の場面ではなくラベルである。「多用した瞬間に温度は装飾になる」がそのまま起きている。絞れば、ナビの現在地とヒーローの点、Where to next の分岐に温度が戻る。

**決めてもらうこと** 砂を句点・分岐点・現在地の3つだけにしてよいか。

## 4. 絵文字を色の系統に含めるか

**現物** .js・.html・.css を U+1F300–1FAFF と U+2600–27BF の範囲で数えた(PM と同じ数え方。★☆♥✓✕ のような、文字の顔でも出る記号を含む)。3つのアプリのソースは、改修で turnaround12 に戻り道を1行足しただけで、絵文字の数は変わっていない。

- ブランドサイト(bridge.css を読むページ): 0個。紹介 LP 系では study-board の見出しに 🔥 が1個ある(前は2個)
- turnaround12: 24個(16種)。結果画面の 46px の紋章は、2026-09-22 までにグレースケールにしてある
- clinic-flow-3d: ソースには 687個(158種)ある(うち197個は線画への対応表 `app/ui/icons.js`)。描画するときに線画 SVG へ置き換わり、画面に残るのはキャンバスの約6か所と CSS の1か所だけ。別のデザイン系なので、第22条は及ばない
- gokigen-gacha: 130個(86種)。うち26個(7種)は ★☆♥♡✓✕☕ のような記号。前回の 108個(82種)は数え方の違いで、ソースは変わっていない(台帳の時点では68個)

**案** A: 色として数え、4系統の外の色は使わない。B: 文字として扱い、量だけを context.md §7 で抑える。

**推奨 A** 実務はすでに A で動いている(紋章のグレースケール化、clinic-flow-3d の線画化)。明文にしておかないと、次のアプリで同じ問いが出る。gokigen-gacha に当てるかどうかは未決事項 #8 と一緒に決め、それまでは触らない。study-board の 🔥 は §5 の LP 系(ブランドの系)にあるので、A なら外す。

> **2026-10-18 追記(憲法 v1.9 起草・PR #165)** — v1.9 で未決事項 #8 が解決し、第22条はブランドの面だけの規定になる(第30条の2)。この問いは、ブランドの面(公式サイトと紹介 LP 系。いまは study-board の 🔥 1個)だけの問いに縮む。turnaround12・clinic-flow-3d・gokigen-gacha の絵文字は、それぞれのデザインの選択になる。LP 系の型は design-system v2.0 で §5 から §4 へ移る。v1.9 を読んでから答えてほしい。

**決めてもらうこと** 絵文字を色として数えるか(v1.9 後はブランドの面について)。

## 5. legal/privacy.html の砂

**現物** 改修で legal/ は変わっていない(bridge.css を読まず、ナビもない)。privacy.html は、h2 2つ(日本語 / English)とリンク2つ(mailto)が、砂 `#7D6845` の直書き。AA は満たしている。同じ型の `legal/support.html` も、h2 3つとリンク2つ(mailto と privacy.html)が砂。

**案** A: 見出しを炭、リンクを藍(`#24365C`)にする。2ファイル、各2行の変更。B: アプリ審査用の別の文書と見なして、現状のままにする。

**推奨 A** 選ぶ場面のない法務文書なので、砂は飾りにしかなっていない。ナビがなく行き止まりになっていることと、ライトでしか表示しないことは、別に §7 へ起票する。

**決めてもらうこと** privacy と support の砂を、炭と藍に替えてよいか。

## 6. OGP 9枚の小見出し

**現物** 改修で `images/ogp/` と生成・再着色のスクリプトは変わっていない。`images/ogp/` には15枚ある。新しい6枚は `scripts/make-ogp.mjs` が `#7D6845` で作ったもの。思想ハブの9枚は生成元がない。ただし、再着色のスクリプト `scripts/recolor-ogp-eyebrow.mjs`(「社長裁可 2026-08-09」と記載)が残っている。このスクリプト自身の判定式で、9枚の小見出しの帯を測った。`#7D6845` に当てはまる画素は133〜288、`#A98F63` に当てはまる画素は69〜130で、9枚とも「適用済み」と判定された。

**案** A: 現状維持にして、台帳の行を閉じる。B: 15枚を同じ版下で作り直す(9枚の書体が変わる)。

**推奨 現状維持** 9枚はすでに `--dawn-deep` になっている。台帳の記述が古いだけである。

**決めてもらうこと** 台帳の行を閉じてよいか。
