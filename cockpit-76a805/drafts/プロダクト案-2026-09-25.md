# プロダクト案の検討(2026-09-25)

社長の「好きなようにさ、プロダクト考えようぜ」への回答。5つの視点(本業の一次体験/現場職の一日/既存のあいだと休止/note の読者/体験・作品)で15案を出し、3つの目(憲法と誠実の条項/忙しい利用者の現場/事業・運用・実装)で採点し、PM が1案に絞った。実装はしていない(dev-loop の product-idea)。

同じ夜、社長から「note の URL を入れると、どんな分野の読み手に刺さるか分かるとよい」と方向が出たため、実装はそちら(宛先しらべ・atesaki-76a805)を先に行った。以下はその前の検討の記録で、次に何を作るかを決めるときの材料として残す。

## 推奨案

### 場面を添える(仮称)

言いかえ帳で星を付けた言葉に、自分が実際にやった場面を1つずつ添えて、職務経歴書の1項目としてコピーできるようにします。

#### 現状の問題

言いかえ帳の「あつめた言葉」には、「コピーした言葉には、自分が実際にやった場面をひとつ添えてから使ってください」と書いてあります(iikae/index.html 85行)。コピーした文にも同じ注意が入ります(app.js 209行)。ところが、場面を添える手段がありません。

場面は、棚卸しの答え(localStorage `tanaoroshi_v1` の answers。場面・やったこと・そのあとの変化)にすでに入っています。2つの道具は同じ6カテゴリ(patient/team/teach/kaizen/risk/org)を使っていますが、データはつながっていません。棚卸しの「職務経歴書のたね」も、見出しはカテゴリごとの決まり文句(INTERVIEW.opener)で、本人の経験に固有の名前が付きません。

#### 利用者に起きている不便

職務経歴書を書こうとしている看護師・リハ職が、棚卸しと言いかえ帳を行き来し、メモ帳で手作業で組み合わせています。組み合わせないまま言いかえだけを貼ると、面接で「具体的には」と聞かれたときに答えられません。

#### 変更内容(何を作るか)

- 「あつめた言葉」の各行に「場面を添える」を足します
- 同じカテゴリで棚卸しに書いた答えを並べます。1つ選ぶと、その言葉の「成り立つ条件」(joken。54件すべてにあります)が開き、「当てはまる/当てはまらない」の2択になります
- 「当てはまる」を選ぶと、その答えと言葉が対になります。「当てはまらない」を選ぶと、対にしません。盛らないための手順を、操作の中に入れます
- 棚卸しの答えが0件のとき(別の端末で棚卸しをした人もここに入ります)は、「この言葉が当てはまる場面を1行」の任意欄と、棚卸しへのリンクを出します
- 「職務経歴書の形でコピー」: 対になった言葉は「【状態に合わせた体位管理と褥瘡予防】皮膚の発赤を見て、向きと間隔を変えていた。」の形で書き出します。対のない言葉は、いまと同じ形で書き出します

#### 変更後の利用イメージ(画面の流れ)

1. 言いかえ帳の「あつめた言葉」を開きます(いまの画面です)
2. 星を付けた言葉の「場面を添える」をタップすると、棚卸しの答えが3行ずつ並びます
3. 答えを1つタップすると、成り立つ条件が開きます。「当てはまる」をタップすれば対ができます
4. 最後に「職務経歴書の形でコピー」をタップします

操作は言葉1つにつき2〜3タップです。答えが0件のときだけ1行を書きます。

#### 実装対象のファイル

- `iikae/app/app.js`: 添える画面、対の保存、コピーの形。`kotoba_v1` を `{saved, pairs}` に広げます(pairs は `{genba: {q: 質問index} | {text}}`)。pairs のない古いデータもそのまま読めるようにします
- `iikae/index.html`・`iikae/app/styles.css`: 画面の器を足します。部品は shared/bridge.css の既存のもので組みます(designer が確認します)
- `tanaoroshi/index.html`: Step 3 にある言いかえ帳への導線文を1行差し替えます(「星を付けた言葉に、ここで書いた場面を添えられます」)
- `tanaoroshi/app/data.js`: 冒頭のコメントに1行足します(「質問の順番を変えたら、iikae の対応表も直す」)
- 新しいディレクトリ・PRODUCTS 配列・sitemap は変えません。台帳は iikae の note だけを更新します

#### 既存機能への影響

- 棚卸しのデータは読むだけで、書き換えません。`tanaoroshi/app/data.js` は読み込みません(ROLES・CATEGORIES がグローバルの const なので、読み込むと衝突して SyntaxError になります)。代わりに、質問index→カテゴリの18件の対応表を iikae 側に持たせます
- Compass とは重なりません。Compass が扱うのは経験の使い道(橋)で、個人の場面と対にする機能はありません
- 実物の確認中に別件が見つかりました。Compass の結果画面(compass/app/app.js 228行)に「BRIDGE MAPに残しておきます」とありますが、localStorage の処理が1つもなく、何も残りません。第13条に照らして、この案とは切り離して先に直します(文言を直すか保存を実装するかは、社長に決めてもらいます)

#### 実装上の注意点

- 外部通信・AIはありません。棚卸しの自由記述には患者さんの話が入りうるため、画面に出すだけにして、どこへも送りません
- 第31条の申告案です。言いかえ帳の段階は「理解」のままとし、添える画面は理解で得た名前を「設計」(職務経歴書で使える形)へ渡す段と書き足します。serves は変えません
- 測り方(第15条)は2つです
  - 端末内で数えるもの: 対の数、「当てはまらない」を押した数、0件の人が1行を書いた数
  - 人に試してもらうもの: 社長と協力者3人に、棚卸し→言いかえ帳→添えるを通しでやってもらい、できた1項目を見せてもらいます
- 判定の基準です。対が1件以上でき、「当てはまらない」が一度でも押されたら効いたと書きます。添える画面に来た人の大半が0件で、1行も書かないまま離れたら、効かなかったと書きます。どちらの結果も台帳に残します

#### 推奨する理由

- **反論1「両方を同じ端末で使った人にしか効かない」**: 0件のときに1行で添えられる逆向きの道を最初から入れます。星を付けた人なら全員が使えます
- **反論2「新しいプロダクトではなく、一画面にすぎない」**: 15案のうち、どのレンズでも最低点が3以上だった6案で比べました。制度の事実も、本業の案件情報も、看護側の照合も要らず、社長の照合待ちで止まらないのはこれだけです。既存の2点に新しい入力をほぼ足さず、いま公開している注意書きの約束を果たします。「1を5にする」型です
- **反論3「キャリアログと同じ理由で止まらないか」**: 止まらないと考えます。キャリアログが止まった原因は、毎日の記録と遠い読み手でした。この画面は新しい記録を求めず、読み手は来週の面接官です
- **反論4「社長は転職活動中ではない(第12条)」**: 社長には次の2つで最初の使い手になってもらいます
  - PTから事業会社へ移ったときの経歴を通しで入れ、当時の職務経歴書と比べて検算する
  - 本業で応募書類を読む立場から、「見出しと場面1文」の形が効くかを判定する

  「使い続ける」は言いかえ帳・棚卸し本体の課題として残ります。この画面がそれを悪化させることはありません

## 社長への確認

1. PTから事業会社へ移ったときの職務経歴書は手元にありますか。棚卸し→言いかえ帳→添えるを社長の経歴で通して、当時の書類と比べる1件目の検算に使ってよいですか
2. 本業で応募書類を読むとき、言葉だけ立派で具体を聞くと出てこない書類はどのくらいありますか。「言いかえの見出し+自分の場面1文」の形は、読む側として実際に効きますか
3. 今回の「プロダクト」は、新しい道具を1本出すという意味でしょうか。そうであれば、直近に求人票を書く採用案件か、電子カルテ移行の案件はありますか(代替案のどちらを先にするかをここで決めます)
