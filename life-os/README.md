# LIFE//OS

> 今日の自分を起動した瞬間に、いまどんな状態なのかが一目で分かる、自分専用のOS

毎日30秒の入力から、5つの状態（ENERGY / FOCUS / MOOD / BODY / SOCIAL）を割り出して表示する
パーソナルダッシュボードです。登録不要・端末内保存・オフライン対応。

公開URL: https://bridge-med.jp/life-os/

---

## コンセプト

TODOアプリでも、習慣管理アプリでも、日記アプリでもありません。

生活のログを取らせること自体を目的にせず、**「いまの自分がどの状態で、今日は何をどこまでやれるのか」**
を朝の数秒で判断できるようにするための道具です。

- 数字が主役です。大きな数値、小さなラベル、繊細な線で構成しています
- 押し付けません。「がんばりましょう」とは言わず、OSからの指示のように短く出します
- 続けられることを前提に設計しています。入力は5問、所要は30秒です

### 道具としての自己申告（CONSTITUTION.md 第31条）

- **思考の型のどの段階を支えるか** — 「評価」と「再評価」。今日の状態を測り、
  一日の終わりに測り直し、翌日の判断材料にします
- **誰の、どんな選択肢を増やすか** — 交代勤務やオンコールで生活のリズムが崩れやすい対人援助職が、
  「今日は攻める日か、引く日か」を感覚ではなく自分の記録から選べるようにします

## 使用方法

### はじめかた

1. URLを開きます。初回と、その日はじめて開いたときだけ2秒ほどの起動シーケンスが流れます
   （画面をタップすれば飛ばせます）
2. 「状態を入力する」から5問に答えます。スライダーと5段階の選択だけです
3. SYSTEM STATUS に5つの数値と、TODAY MISSION（1〜3件）が出ます

### 一日の使い方

| 場面 | 操作 |
|---|---|
| 朝 | INPUT で5問に答える。HOME で状態とミッションを見る |
| 日中 | LOG から出来事を記録する（仕事・運動・食事・睡眠・酒・サウナ・外出・人と会った・その他） |
| 夜 | HOME の END DAY で締める。DAY SCORE と評価、短い講評が出ます |
| ときどき | HISTORY で7日・30日・90日の推移と、INSIGHTS で自分の傾向を見る |

ログは行をタップすれば編集・削除できます。ログを足すと、その日の状態も計算し直します。

### 入れ忘れた日を、あとから埋める

1日忘れても履歴に穴を残さずに済みます。LOG で日付を戻し、
「この日を入力する」から5問に答えれば、その日の状態が入り、履歴と分析にも反映されます。
入力済みの日も「入力し直す」からやり直せます。

続けられなかったことを責める作りにはしていません（CONSTITUTION.md 第9条4号）。

### 動作を先に見たいとき

まだ1件も記録がない状態では、HOME に「見本を見る」が出ます。45日分の見本データが入り、
HISTORY と INSIGHTS の動きをそのまま確認できます。

見本が入っているあいだは HOME の先頭に帯が出て、それが自分の記録ではないことを常に示します。
帯の「消す」か、MENU の「デモデータ」スイッチで消せます。既定では1件も入っていません。

### ホーム画面に追加する

PWA対応です。iPhone / iPad は Safari の共有ボタンから「ホーム画面に追加」、
Android は Chrome のメニューから「アプリをインストール」を選びます。
追加すると全画面で開き、オフラインでも動きます。

### 隠し要素

5つ入れてあります。ここでは2つだけ書いておきます。

- ロゴ（LIFE//OS）を5回押すとターミナルが開きます。`help` でコマンド一覧が出ます
- 5項目すべてが80以上になった日には、専用の表示が出ます

残りは使っているうちに出てきます。

## 技術構成

| 層 | 使っているもの |
|---|---|
| 画面 | HTML + CSS（カスタムプロパティによるトークン管理）+ 素のJavaScript |
| 図 | 手書きのSVG（円形ゲージ・スパークライン・折れ線チャート） |
| 保存 | localStorage（キーは `lifeos.v1`） |
| オフライン | Service Worker（`sw.js`、cache-first、同一オリジンのみ） |
| 依存 | なし（ビルド不要・npm不要・外部APIなし・通信なし） |

### 依頼時の指定（Next.js / TypeScript / Tailwind / shadcn/ui / Framer Motion / Recharts）との違い

このリポジトリはビルドを持たない静的サイトで、GitHub Pages にそのまま配信されます
（`CLAUDE.md`「静的サイト。ビルドなし」、`docs/context.md` 10章「複雑すぎない技術選定」
「不要な依存関係を増やさない」）。指定のスタックを持ち込むと `node_modules` とビルド生成物を
抱えることになり、既存の全プロダクトと運用が分かれます。

そのため**機能要件はすべて満たしたうえで、実装は依存ゼロの静的アプリに置き換えています**。
localStorage・オフライン動作・ログイン不要・外部API不要・PWA・アニメーションという
指定の中身は変わりません。チャートは Recharts の代わりに手書きのSVGで、
折れ線・凡例・クロスヘア・ツールチップ・平均行まで実装しています。

### 色について

（明度帯・彩度下限・色覚多様性での分離・通常視での分離・面とのコントラスト）を
ライト／ダーク両方で通したものだけを使っています。全ペアでの検査も通しています。

| 項目 | ダーク | ライト |
|---|---|---|
| ENERGY | `#BD871F` | `#A9760C` |
| FOCUS | `#2CA4BA` | `#00829B` |
| MOOD | `#9282EA` | `#6553C6` |
| BODY | `#3D7A2E` | `#24660F` |

## データ構造

すべて端末内の localStorage に1つのキー（`lifeos.v1`）で保持します。外部へは送信しません。

```jsonc
{
  "version": 1,
  "createdAt": "2026-08-15T08:00:00.000Z",
  "settings": {
    "theme": "dark",          // dark | light
    "lastBootKey": "2026-08-15",
    "seen": {},               // 演出の既読フラグ
    "unlocked": [],           // 解放した隠し要素
    "demo": false             // デモデータが入っているか
  },
  "days": {
    "2026-08-15": {
      "date": "2026-08-15",
      "startedAt": "07:42",   // その日はじめて開いた時刻
      "input":   { "sleep": 7.0, "condition": 4, "sharpness": 5, "social": 3, "stress": 2 },
      "inputAt": "2026-08-15T07:45:12.000Z",
      "status":  { "energy": 84, "focus": 90, "mood": 72, "body": 81, "social": 63 },
      "missions": [{ "id": "work:DEEP WORK", "text": "…", "tag": "DEEP WORK", "color": "focus", "done": false }],
      "events": [{ "id": "…", "type": "drink", "time": "22:36", "note": "", "qty": 2 }],
      "report":  { "score": 84, "grades": { "energy": "A" }, "comment": "…", "endedAt": "…" }
    }
  }
}
```

### 一日の境界は 04:00 です

深夜1時に取ったログは前日に属します。夜更かしを翌日に繰り上げてしまうと、
「前夜に飲んだ／夜更かしした」という事実が翌日の計算に効かなくなるためです。

### 書き出しと取り込み

MENU からJSONで書き出し・取り込みができます。端末を替えるときや、
消す前の退避に使ってください。

## スコア計算の考え方

外部のAIは通していません。すべて端末内のルールベースです。
`app/engine.js` にすべて書いてあり、アプリ内でも確認できます
（隠しコマンドのひとつが、この重み表を開きます）。

### 1. 入力の正規化

| 入力 | 変換 |
|---|---|
| 睡眠時間 | 7.5時間を頂点に0〜1へ。不足側は急に（3時間で0）、過多側はゆるく（10時間で0.58）落とします |
| 体調 / 冴え / 話したい気分 | 1〜5 を 0〜1 に線形変換 |
| ストレス | 1〜5 を 0〜1 にしたうえで反転（calm = 1 − strain） |

睡眠だけ非線形にしているのは、寝不足の1時間と寝すぎの1時間が同じ重さではないからです。

### 2. 5項目の算出

```
ENERGY = 100 × (睡眠 .40 + 体調 .30 + 落ち着き .18 + 冴え .12) − 前夜の酒 11 − 夜更かし 6
FOCUS  = 100 × (冴え .44 + 睡眠 .26 + 落ち着き .18 + 体調 .12) − 前夜の酒  6 − 夜更かし 7
MOOD   = 100 × (落ち着き .34 + 体調 .26 + 社交 .22 + 睡眠 .18) + 運動 6
BODY   = 100 × (体調 .46 + 睡眠 .28 + 落ち着き .16 + 冴え .10) − 前夜の酒 8 + 運動 5
SOCIAL = 100 × (社交 .55 + 体調 .20 + 落ち着き .15 + 睡眠 .10) + 人と会った 4
```

補正の材料はイベントログから取ります。

- 前夜の酒 … 前日の `drink` の杯数 ÷ 3（上限1.0）
- 夜更かし … 前日のログの最終時刻が 01:00 以降なら 1
- 運動 … 当日に `exercise` または `sauna` のログがあれば 1

最後に0〜100で丸めます。ログを足すと、その日と翌日の状態を計算し直します。

### 3. DAY SCORE

```
base = ENERGY .24 + FOCUS .24 + MOOD .20 + BODY .20 + SOCIAL .12
```

これにその日のログから補正を足します。運動 +3 / サウナ +2 / 仕事 +2 / 食事2回以上 +1 /
酒3杯以上 −5（2杯は −2）/ 最終ログが 01:30 以降 −4。

**ログが1件もない日を減点しません。**記録しなかったことを責める設計にはしていません。

評価は S（93以上）/ A（84以上）/ B（70以上）/ C（55以上）/ D（40以上）/ E です。

### 4. INSIGHTS の出しかた

データが少ないうちに結論を出さないよう、3つの条件を全部満たしたものだけを表示します。

1. 記録が **10日以上** ある
2. 比較する2グループが **それぞれ4日以上** ある
3. 平均の差が **3以上** ある

条件を満たさないときは「あと◯日分の記録で、傾向の分析を始めます」と、
足りていないことをそのまま出します。

見ている関係は、睡眠7時間以上とFOCUS / 前日の飲酒とENERGY / 運動とMOOD /
前夜の夜更かしとENERGY / 睡眠6時間未満とDAY SCORE / 人と会った日とMOOD の6つです。

これは相関であって因果ではありません。「この条件の日は平均がこれだけ違った」以上のことは
言わない書きかたにしてあります。

## 今後拡張できる機能

すぐに足せるもの（既存の構造のまま追加できます）

- **入力項目の追加** — `engine.js` の `QUESTIONS` に1つ足し、各式に重みを1項足すだけで増やせます
- **イベント種別の追加** — `EVENT_TYPES` に1行と、`charts.js` の `ICONS` に1つ
- **ミッションの追加** — `MISSION_RULES` に条件と文面を1行。優先度とグループで自動的に整理されます
- **インサイトの追加** — `insights()` の `defs` に1オブジェクト。最低件数の判定は共通で効きます
- **週次・月次レポート** — DAY SCORE の集計は `averages()` がすでに持っています

検討したいもの（設計の判断が要ります）

- **Apple Health / Google Fit からの睡眠と歩数の取り込み** — 入力を5問から3問に減らせます。
  ただし端末内で完結する原則をどう守るかを先に決める必要があります
- **重みの個人最適化** — 蓄積データから各人の係数を回帰で調整する案。
  ただし数式が説明できなくなった時点でこの道具の価値は下がるので、
  「調整前と調整後を両方見せる」形にしないと入れられません
- **通知** — 夜のEND DAYを忘れる人向け。Web Pushはサーバーが要るため、
  端末内で完結する範囲（アプリを開いたときの提示）に留める方が筋がよさそうです
- **キャリアログ / Growth OS との接続** — 「調子がよかった日に何をしていたか」を
  仕事の記録側から引ける導線。BRIDGEの他の道具と重複しない形を先に決める必要があります

## 開発メモ

- ビルドはありません。ファイルを直接編集します
- 出荷前の機械検査 `node scripts/check-site.mjs`（リポジトリのルートから）
- `sw.js` を触ったら `CACHE` の版名を必ず上げます。上げ忘れは既存端末への旧画面の配信になります
- 色はすべて `styles.css` 冒頭のトークンです。ハードコードを足さないでください
