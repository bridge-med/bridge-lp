## 1. Purpose

きれいにするためではない。次の6つを、ひとりで運営しながら保つためにある。

1. **一貫性** — 同じ意味は同じ見た目になる
2. **判断速度** — 迷ったら §4 の部品か §5 の型を使う。発明は最後の手段
3. **実装品質** — 44px・AA・両テーマ・reduced-motion が、部品を使えば自動で満たされる
4. **保守性** — 1か所直せば全ページが直る状態を保つ
5. **BRIDGE らしさ** — 静かだが強い。医療感も IT 企業感も出しすぎない
6. **初見で迷わない** — 押せるものは押せる顔をし、現在地が分かり、行き止まりがない

## 2. Principles

UI に直接効く原則だけを抜き出す。条文は憲法、UI 方針は context.md §7。

| 原則 | UI での判断 |
|---|---|
| Human First(第9条1号) | 機能名より「誰が・いつ使うか」を先に見せる。部品の見栄えより読む人の状況 |
| Expand Choices(第8条・第27条) | 分岐は訪問者の文脈で選べる質のものを並べる。同じ顔の分岐を数だけ増やさない |
| 静かだが強い(第17条) | 装飾・影・動きは足す前に削れないかを問う。強さは余白と構図で出す |
| 交差(第21条・第24条) | 新しい装飾の前に「交差する二本の線」「分岐する道」で表せないかを考える |
| 余白(第23条) | 本文幅は `--text-max`(660px)。余白は削って情報を足す場所ではない |
| 選択の瞬間(第22条) | 砂色は現在地・分岐点・到達・句点にだけ置く。強調色として使わない |
| 歩くサイト(第26条) | 全ページ末尾に Where to next。一本道・行き止まりを作らない |
| 体験は説明に勝る(第28条) | 説明文を足すより、触れる実物(デモ・実画面)への入口を置く |
| 押し付けない(第29条) | CTA は複数の関わり方を並べ、「何もしなくても十分」を一行置く |

## 3. Foundations

値は `shared/bridge.css` の `:root` が唯一の情報源。ここに書くのは役割であり、値を書き写さない。

### 3.1 Color

色は4系統(生成り・藍・砂・炭)。新しい色をトークンに足さない(第22条)。

| 役割 | トークン | 使う場所 | 使わない場所 |
|---|---|---|---|
| 地(生成り) | `--bg` / `--bg-2` / `--bg-3` | ページの地 / 交互のセクション(`.sec.tint`)とフッター / 写しの下地・サムネイルの読み込み前 | — |
| 板 | `--card` | 地から一段浮かせる面(カード・分岐カード) | 地の代わりに全面へ敷く |
| 文字(炭) | `--ink` / `--ink-2` / `--ink-3` / `--ink-4` | 見出し・強調 / 本文 / 補足・ラベル / 区切り・無効に近い記号 | `--ink-4` を読ませる文字に使う(AA 未達) |
| 罫 | `--line` | 罫線・カードの縁・チップの縁 | 面の塗り |
| 骨格(藍) | `--blue` / `--navy` / `--blue-soft` | 主ボタン・リンク・選択中のタグ / ロゴと図の線 / hover の縁 | 大面積の背景 |
| 藍の上の文字 | `--on-fill` | `--blue`・`--glass` で塗った面の上の文字 | 地の上の文字 |
| 温度(砂) | `--dawn` / `--dawn-deep` | 現在地・分岐点・到達・句点、`.eyebrow` の線、`::selection` / **小さい文字として砂を使うときは必ず `--dawn-deep`**(`--dawn` は白地で AA 未達) | 強調・装飾・見出し全体・背景 |
| 夜の帯 | `--dark-sec` / `--dark-sec-text` / `--dark-sec-dim` | 両テーマで暗いままの帯(Manifesto・「何もしなくても十分」の帯) | 1ページに2本以上 |
| ガラスの素材 | `--glass` / `--glass-deep` / `--glass-hi` / `--glass-ink` | **トップと Products だけ**。用途は憲法第22条ガラスの但し書き(v1.4・v1.5)の四つに限る | 文字色・リンク・罫線・他ページ。流用のために新しい用途を作らない |
| 影 | `--shadow` | §3.6 | — |

- ライト/ダークはトークンの差し替えだけで成立させる。ページ側に色を直書きしない(`#fff` も含む)。ダーク用の上書き規則をページに書く必要が出たら、トークンが足りないという合図。
- 実物の写し(スクリーンショット・写真)の内部は色の規律の外。ただし加工しない・色を枠の外へ持ち出さない(第22条 写しの但し書き)。
- グラデーションを足さない。既存は下層ヒーローの地(`--hero-sky-1`→`--bg`)とトップのヒーロー(ガラスの但し書きの範囲)だけ。

### 3.2 Typography

| 役割 | 書体 | 実体 |
|---|---|---|
| 思想の言葉(見出し・ステートメント・分岐の名前) | 明朝 `--mincho` 600 | `.sec-h` `.stmt` `.page-hero h1` `.card-t` `.row-t` `.walk-h` `.walk-card .t` `.walk-note`(400) |
| 構造の言葉(本文・説明・ボタン) | `--sans` | 本文 15px/2.3(`.body-p` `.lead`)、小さな本文 12.5〜13px/2.1(`.card-p` `.row-p`)、ボタン 13px/700 |
| ラベル・英字・数字 | `--en`(Inter) | `.eyebrow` 10px/700/0.24em/大文字、ナビ 10px/600、番号 `.row-num` 11px |
| トップと Products の見出し | `--sans` 900 | 憲法第23条 見出しの但し書き(v1.5)。**他ページへ持ち出さない** |

- 本文の最大幅は `--text-max`(660px)。見出しは `--max` まで広げてよい。
- 見出しに句点・「!」を付けない(第19条)。見出しの折り返しは `text-wrap:balance` と BudouX に任せ、`<br>` で手組みしない(PC だけで改行したいときは `.br-pc`)。
- 数字を並べて比べる表は `font-variant-numeric:tabular-nums`。
- **未決**: 明朝の適用範囲(思想の言葉とは何か)は憲法 未決事項 #10。新しいページで迷ったら、上の表の「既存と同じ役割か」で決め、新しい役割なら designer 経由で社長判断に上げる。

### 3.3 Spacing

4px/8px の体系は置かない。既存の実装は「段の大きさ」で揃っている。

| 段 | 値 | 用途 |
|---|---|---|
| セクションの上下 | `--sec-y` = clamp(100px,14vh,180px) | `.sec` `.walk`。一覧が長いページの詰めた版は clamp(64〜72px, 9〜10vh, 100〜120px) |
| 見出しから本体まで | clamp(36px,5vh,52px) 〜 clamp(44px,6vh,64px) | 見出しブロックの下、一覧・図の上 |
| 部品の間 | 14〜18px | グリッドの gap(`.grid-3` 18px、`.walk-grid` 14px) |
| チップの間 | 6〜8px | `.facts` `.tag-row` |
| 左右の余白 | `--pad-x` = clamp(24px,6vw,96px) | 全ページ共通 |

新しい値を作る前に、この5段のどれかに寄せる。セクション内の余白を詰めて情報を足すのは、余白を削る行為である(第23条)。

### 3.4 Layout

- 幅: 全体 `--max`(1180px)、本文 `--text-max`(660px)。`.sec > .sec-inner` で中央に置く。
- 段組: 3列(`.grid-3`)を上限の目安にする。`.walk-grid` は3分岐。
- ブレークポイントは3つだけ使う。
  - **920px** — ナビがドロワーに切り替わる。QA の「モバイル」はこの幅以下
  - **760px 前後** — 3列が1列に畳まれる(`.walk-grid`、ヒーローの構図)
  - **600px** — 最後の1列化(`.grid-*`)
  - 860px(`.row` `.footer-grid`)・960px(`.grid-3/4`)は既存の例外。新規は上の3つに寄せる
- 固定ヘッダーぶんのアンカーずれは `scroll-margin-top:90px`(共通で適用済み)。

### 3.5 Radius

**角丸を使うことと、カードにすることは別の判断である。** 角丸は「何か」を表す手段で、囲う理由にはならない(第24条・context.md §7「すべてをカードで囲わない」)。

| 段 | 値 | 意味 | 実体 |
|---|---|---|---|
| Pill | 100px | 押せる小さなもの・事実のラベル | `.btn` `.nav-cta` `.tag` `.chip` `.facts li` |
| Soft | 16〜18px | 汎用の板(1ページに多用しない) | `.card`、community の `.way-card`、journal の `.j-card`(16) |
| Edge | 2〜6px | 写し・展示・分岐。実物を包む枠は角を立てる | `.walk-card`(2) `.prod-card`(4) トップ `.pick`(6)、サムネイル(3) |
| 円 | 50% | 点と丸ボタン | `.theme-btn`、道のりの点 |

新しい半径を足さない。どれにも当てはまらないときは、その要素を囲う必要があるかを先に問う。

### 3.6 Shadow

影は「持ち上がっている=押せる・独立している」ことの表明にだけ使う。装飾で足さない。

- `--shadow` — `.card` の常時の浮き、主ボタンの hover。
- 分岐カード・展示カード(`.walk-card` `.prod-card` `.pick`)は影を持たず、hover で縁の色(`--blue-soft`)と 3px の浮上で応答する。**新しい部品はこちらを既定にする。**
- 夜の場の実画面の影(トップ)はガラスの但し書きの範囲の一点物。

### 3.7 Motion

動きは派手にするためではなく、**構図・主役・現在地の変化を伝えるため**に使う。

| 用途 | 実体 | 時間・緩急 |
|---|---|---|
| 登場(スクロールで現れる) | `[data-reveal]` + `data-reveal-delay="1〜4"` | 1s・`--ease`。0.1s 刻みで最大4段 |
| hover(進めることを触覚的に) | 浮上 2〜4px・縁の色・矢印の移動 | .2〜.35s・`--ease` |
| 開閉 | ドロワー・ナビの背景 | .35〜.5s・`--ease` |
| 署名 | 下層ヒーローの二本線を描く | 2.4s・一度だけ |
| 場面の転換 | トップの固定ステージ | スクロール連動(トップ専用) |

- 緩急は `--ease`(cubic-bezier(.16,1,.3,1))の1本。新しい曲線を足さない。
- `prefers-reduced-motion: reduce` では登場・署名・場面転換を止め、最初から完成した姿を見せる(共通 CSS で処理済み。ページ独自の動きは各ページで同じ扱いにする)。
- JS が動かない環境で中身が透明なまま残らないこと(`html.js` 配下だけで隠す+安全弁 `rv-safe`)。
- 常時ループする動きは1ページに1つまで(トップの光の帯)。画面外・非表示では止める。

### 3.8 Theme

- `data-theme="light|dark"` を `<html>` に置く。初期値は保存値 → OS 設定の順(各ページ `<head>` の同期スクリプト)。切り替えは `.theme-btn`(§4)。
- 両テーマは等価に設計する(第22条)。片方だけで確かめた変更は未完成。

## 4. Components

すべて `shared/bridge.css` にあり、ナビ・フッター・ヒーローの線は `shared/bridge.js` が描く。
**新しい UI を作る前に、この表で表現できないかを必ず確かめる。**

| 部品 | クラス | 目的 | 使うとき | 使わないとき |
|---|---|---|---|---|
| Navigation | `.site-nav`(JS 描画) | 全ページの地図の入口 | 常に。ページ追加は `NAV` 配列に1行 | ページごとに独自ナビを書く |
| Mobile Navigation | `.nav-drawer` `.drawer-item` | 説明付きの「探索の地図」 | 920px 以下で自動 | 説明を省いてリンクだけにする |
| Theme toggle | `.theme-btn` | ライト/ダークの切り替え | ナビに1つだけ | ページ内に2つ目を置く |
| Footer | `.site-footer`(JS 描画) | 最後にもう一度地図を渡す | 常に | ページ独自のリンク集をフッターに足す |
| Page hero | `.page-hero` `.crumb` `h1` `.lead` | 下層ページの入口。1ページ=1つの問い | トップ以外のページ | 2つ目のヒーローを置く |
| Breadcrumb | `.page-hero .crumb` | 3階層の現在地 | 下層ページ | 4階層目を作る(ia.md §2) |
| Section | `.sec` `.sec.tint` `.sec-inner` `.eyebrow` `.sec-h` `.body-p` `.stmt` | ページの段 | 章ごとに1つ。`.tint` は交互に | 1段に見出しを2つ |
| Button | `.btn.primary` `.btn.ghost`(トップと一覧だけ `.btn.glass`) | 行動の入口 | 主は1画面に1つ。他は ghost | 主ボタンを1画面に2つ置く・文中のリンクの代わりにする |
| Card | `.card` + `.card-tag/-t/-p/-link` | 独立した対象を並べる板 | 対象が独立していて、並べて比べる意味があるとき | 文章の段落・連続した手順・1個だけのもの |
| Row | `.rows` `.row` | 番号・名前・説明の一覧 | 数が多い、または順序がある一覧 | 2〜3件の比べる対象(Card) |
| Chip(状態) | `.chip` | 状態を示すラベル(押せない) | 「稼働中」「構想中」などの状態(Projects) | 押せる UI |
| Facts | `.facts` | 確認済みの事実(無料・登録不要など) | 利用条件 | 宣伝文句・未確認の性能 |
| Tag(選べる) | `.tag-row` `.tag` `.tag.active` | 絞り込み | 一覧の絞り込み(Journal) | 状態表示(Chip) |
| Where to next | `.walk` `.walk-grid` `.walk-card` `.walk-note` | 行き止まりを作らない3分岐 | **全ページ末尾** | 3分岐の中身を同じ顔にする |
| Reveal | `[data-reveal]` | 登場 | 段の単位 | 本文の1行ずつ |

### States と Accessibility(実在するものだけ)

| 部品 | 実装済みの状態 | 守ること |
|---|---|---|
| Navigation | hover(砂の下線が伸びる)/ 現在地 `.active` + `aria-current="page"` / スクロール後の背景 | 現在地は砂の下線=選択の瞬間 |
| Mobile Navigation | 開閉 `aria-expanded` / `aria-label` の切り替え | ハンバーガーは見た目 38px・タップ 44px |
| Theme toggle | hover | 見た目 34px・`::after` でタップ 44px。`aria-label` あり |
| Button | hover(浮上)| 主ボタンの文字は `--on-fill`。高さ 45px |
| Card / Walk card | hover(浮上+縁) | リンクのときは `<a class="card">` で全体を押せる |
| Tag | hover / `.active` | タップ 44px(`::after` で拡張) |
| Breadcrumb・Logo・Privacy | hover | 見た目は小さいまま `::after` でタップ 44px |

- **focus**: 共通のフォーカスリングは未整備(Gap B-1)。独自に書くときは `outline:2px solid var(--blue);outline-offset:2〜3px`(トップ・一覧の既存と同じ)。
- **disabled / loading / selected**: ブランドサイトに実装はない。必要になったときに §7 の手順で足す。先に作らない。

## 5. Patterns

部品より上の「画面の作り方」。

### Page opening
- 下層は `.page-hero` 一つ。`eyebrow`(英字)→ 明朝の h1(1ページ=1つの問い、ia.md §2)→ リード 1〜2文。
- トップだけは固定ステージ(ia.md §4・憲法第22条 v1.5)。この型を他ページへ複製しない。

### Content hierarchy
- 1画面に主役は1つ。1セクション=1つの見出し+1つの本体(一覧・図・文章のどれか)。
- 説明を足したくなったら、先に削れる文・別ページへ送れる詳細を探す(context.md 開発者の人物像 §4・§10)。
- カードのグリッドは1ページに1か所まで(第24条「その他」フォルダ)。順序があるなら Row か道のり、連続した文章ならカードにしない。

### Choice
- 選択肢は Where to next の3分岐が基本形。3つは「読む/話す/使う」など関わり方が違うものにする(第27条)。
- 分岐カードは Edge の角・影なし・砂の英字ラベル(`--dawn-deep`)。

### Navigation(歩くサイト)
- ナビ・ドロワー・フッターは `NAV` 配列から自動で揃う。ページに地図を手書きしない。
- 行き止まりを作らない。エラー(404)・空の状態も含めて、必ず次へ歩ける入口を置く。

### CTA
- 一つの行動へ追い込まない。主ボタン1つ+ ghost または文字リンク、そして `.walk-note`「何もしなくても十分」の一行(第29条)。
- 購入・登録を急かす言葉・カウントダウン・残数表示を置かない。

### 道のり(順序のある段)
- 横一列に点を並べ、最後の点だけ砂で塗る(到達=選択の瞬間)。900px 前後で縦の線に畳む。
- 実体は各ページのローカル CSS(projects `.road`・services `.flow`・philosophy `.tf-flow`・about `.tl`)。同じ型が4か所にあるため共通化の候補(Gap B-2)。新しく使うときは、このどれかを写さず共通化してから使う。

### 砂の縦線の注記
- 左に 2px の砂の線を引いた段落。引用・正直な注記・語源など「ここで立ち止まる」一文に使う(stories `.story-q` `.honest`、services `.fee`、philosophy `.etym`)。
- 1ページに2つまで。Gap B-3 で共通化の候補。

### Empty / Error / Success / Loading

| 状態 | 現状 | 標準 |
|---|---|---|
| Error | `404.html` — 砂の線を点線にしたロゴ、明朝の一文、3つの出口 | エラーは責めず、次の道を3つ渡す |
| Empty | Journal `.j-empty` — 「まだありません」+ 別の行き先 | 一文+別の行き先。空であることを隠さない |
| JS なし | Products・Projects の `<noscript>` | 一文+直接開けるリンク |
| Loading | 実装なし(静的サイト) | 読み込み前は `--bg-3` の地と `aspect-ratio` で領域を確保し、ずれを起こさない。スピナーは作らない |
| Success | 実装なし(フォームがない) | フォームを持つときに §7 で決める |

## 6. Product Design Systems(Level 3)

ブランドサイトと Product UI を同じ見た目にしない。プロダクトは子であり、道具として最適な顔を持ってよい(第30条)。

| 系 | 対象 | 見た目の規律 |
|---|---|---|
| プロダクト紹介 LP 系 | `shared/subpage.css`(+ `hub.css`)を読む9ページ(medboard・rehaboard・hire-board など) | 同じ4系統をトークン名違いで持つ(`--paper`=`--bg`、`--serif-jp`=`--mincho`、`--sans-en`=`--en` など)。角は Edge(2px)、ボタンは四角の `.buy-btn`。Where to next は bridge.css から移植済み。統合は Gap B-4 |
| Clinic Town 3D | `clinic-flow-3d/` | 憲法とは別のデザイン系(2026-09-12 社長発効・全文は context.md 冒頭)。第22〜24条は適用しない。基準は `clinic-flow-3d/docs/ux-audit-v85.md` §4。アイコンは線画 SVG(`app/ui/icons.js`)で、絵文字を使わない。**ブランドサイトの見た目へ戻さない** |

どの系でも守るもの(ここは例外を作らない):

- 第8条(判断材料を隠さない)・第15条(測ってから語る)・第19条3〜4号・三分法(ゲーム類型)
- タップ領域 44px 以上、文字のコントラスト AA
- スマートフォン最優先、ライト/ダーク(対応するなら等価に)、`prefers-reduced-motion`
- 一画面の情報量を抑える・文字量を抑える(context.md §7)
- 押し付けない(継続・購入を迫る表現をしない)

プロダクト固有の見た目を新しく認めるのは社長の判断であり、根拠は憲法 未決事項 #8 の整理を待つ。designer はその判断材料(なぜブランドの系では足りないか)を揃える。

## 7. 増やすときの規則

新しい Component / token / pattern を足す前に、designer が次の5つを判断する。1つでも「いいえ」なら足さない。

1. 既存の部品(§4)・型(§5)で表現できないか
2. 一画面だけの特殊事情ではないか
3. 今後、再利用される見込みがあるか(実際に2か所目が現れているか)
4. BRIDGE の世界観に必要か(交差・余白・選択の瞬間で説明できるか)
5. ひとり運営の保守コストに見合うか

- **一度しか使わないもの**は、そのページの `<style>` に置く。共通へ昇格させない(第14条・空室の禁止の UI 版)。
- **同じ UI が3か所以上で独自に実装されていたら**、共通化を検討する(§5 道のり・砂の縦線の注記が該当)。共通化は見た目を変えずに行い、1か所ずつ置き換える。
- **トークン**は役割の名前で足す(色名で足さない。例: `--glass` は素材名)。値の追加は色数の増加に当たらないかを第22条で照合する。
- **使われなくなった部品・トークン**は、全ページで未使用を確かめてから消す(Gap B-5)。
- 憲法に触れる判断(色・書体・署名の例外)は designer が決めない。PM・auditor 経由で社長の判断に上げる(第33条)。
