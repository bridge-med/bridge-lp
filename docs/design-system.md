## 1. Foundations

値は `shared/bridge.css` の `:root` が唯一の情報源。ここには役割だけを書く。

### Color

| 役割 | トークン | 使う | 使わない |
|---|---|---|---|
| 地 | `--bg` `--bg-2` `--bg-3` | ページの地 / 交互のセクション・フッター / 写しの下地 | — |
| 板 | `--card` | 地から一段浮かせる面 | 地の代わりに全面へ敷く |
| 文字 | `--ink` `--ink-2` `--ink-3` | 見出し / 本文 / 補足・ラベル | — |
| 記号 | `--ink-4` | 区切り・矢印 | 読ませる文字(AA 未達) |
| 罫 | `--line` | 罫線・縁 | 面の塗り |
| 骨格(藍) | `--blue` `--navy` `--blue-soft` | 主ボタン・リンク・選択中 / ロゴと図の線 / hover の縁 | 大面積の背景 |
| 塗りの上の文字 | `--on-fill` | `--blue`・`--glass` の面の上の文字 | 地の上の文字 |
| 温度(砂) | `--dawn` `--dawn-deep` | 第22条の「選択の瞬間」(句点・分岐点・現在地)。**小さい文字の砂は必ず `--dawn-deep`**(`--dawn` はライトで AA 未達) | 強調・装飾・背景 |
| 夜の帯 | `--dark-sec` 系 | 両テーマで暗いままの帯(Manifesto など) | 1ページに2本以上 |
| ガラスの素材 | `--glass` 系 | **トップと Products だけ**。用途は第22条ガラスの但し書き(v1.4・v1.5)の四つ | 文字色・リンク・罫線・他ページ |

- 両テーマはトークンの差し替えだけで成立させる。色を直書きしない(`#fff` も)。ページにダーク用の上書きが要るなら、トークンが足りないという合図。
- グラデーションを足さない。写し(スクリーンショット・写真)の内部は第22条 写しの但し書きに従う。

### Typography

| 用途 | 書体 | 実体 |
|---|---|---|
| 明朝で組んでいるもの(現状) | `--mincho` 600 | `.sec-h` `.stmt` `.page-hero h1` `.card-t` `.row-t` `.walk-h` `.walk-card .t`、`.walk-note`(400) |
| 本文・説明・ボタン | `--sans` | 本文 15px/2.3(`.body-p` `.lead`)、小さな本文 12.5〜13px(`.card-p` `.row-p`) |
| ラベル・英字・番号 | `--en` | `.eyebrow` 10px/700/0.24em、ナビ 10px |
| トップと Products の見出し | `--sans` 900 | 第23条 見出しの但し書き(v1.5)。他ページへ持ち出さない |

- 本文の幅は `--text-max`。見出しの折り返しは `text-wrap:balance` と BudouX に任せ、`<br>` で手組みしない(PC だけの改行は `.br-pc`)。
- **未決**: 明朝の適用範囲は未決事項 #10。新しい文字の役割で迷ったら、既存と同じ役割かで決め、新しい役割なら designer 経由で社長に上げる。

### Spacing・Layout

- 4px/8px の体系は置かない。既存の段に寄せる: セクション上下 `--sec-y` / 見出しから本体 clamp(36〜44px, 5〜6vh, 52〜64px) / 部品の間 14〜18px / チップの間 6〜8px / 左右 `--pad-x`。
- 幅は `--max`(全体)と `--text-max`(本文)。`.sec > .sec-inner` で中央に置く。
- ブレークポイントは既存の **920(ナビがドロワーに)/ 860 / 760 / 600** に寄せる。900・720・640・520 を新しく作らない。QA の「モバイル」は 920px 以下。

### Radius と Shadow

**角丸を使うことと、カードにすることは別の判断である**(第24条・context.md §7)。角と影は対で使う。

| 段 | 値 | 影 | 意味 | 実体 |
|---|---|---|---|---|
| Pill | 100px | なし(主ボタンの hover のみ `--shadow`) | 押せる小さなもの・事実のラベル | `.btn` `.nav-cta` `.tag` `.chip` `.facts li` |
| Soft | 16〜18px | `--shadow` | 汎用の板(1ページに多用しない) | `.card` `.way-card` `.j-card` `.founder-photo` |
| Edge | 2〜6px | なし(hover で縁の色+3px 浮く) | 分岐・展示 | `.walk-card` `.prod-card` `.pick` |
| 円 | 50% | — | 点・丸ボタン | `.theme-btn`、道のりの点 |

Soft を多用しない(第24条)ので、新しい部品はまず Edge で考える。新しい半径・新しい影を足さない。

### Motion

動きは構図・主役・現在地の変化を伝えるために使う。派手にするためには使わない。

- 登場は `[data-reveal]`(1s・`data-reveal-delay` 1〜4)。hover は浮上 2〜4px・縁の色・矢印(.2〜.35s)。緩急は `--ease` の1本。
- `prefers-reduced-motion` では完成した姿を最初から見せる(共通 CSS で処理済み。ページ独自の動きも同じ扱い)。JS なしで中身が透明のまま残らないこと。
- 常時ループはトップのスクロールの合図だけ。トップの光の帯は間欠(登場で一度・待機中は 10 秒に一度、約 2.6 秒で渡る。画面外・非表示タブ・場面2では渡らせない)。トップの登場演出は約 3.2 秒で待機へ移り、スクロール・キー操作で即座に終える。他ページに足すときは §6。

## 4. Patterns

- **Page opening** — 下層は `.page-hero` 一つ(eyebrow → h1 → リード1〜2文)。トップの固定ステージは他ページへ複製しない。
- **Content hierarchy** — 1画面に主役1つ。1セクション=見出し1つ+本体1つ。説明を足す前に削れる文を探す。カードのグリッドは1ページ1か所まで。
- **Choice** — 基本形は Where to next の3分岐。3つは関わり方の違うもの(読む/話す/使う)にする(第27条)。
- **Navigation** — 地図は `NAV` 配列から自動で揃う。404・空の状態も含めて行き止まりを作らない(第26条)。
- **CTA** — 主ボタン1つ+ghost か文字リンク+`.walk-note`「何もしなくても十分」(第29条)。急かす言葉・残数・カウントダウンを置かない。
- **道のり** — 横一列の点、最後の点だけ砂、860〜900px で縦に畳む。4ページに重複あり(B-2)。新しく使うときは写さず、共通化してから使う。
- **状態**

| 状態 | 現状 | 標準 |
|---|---|---|
| Error | `404.html`(点線の二本線・一文・3つの出口) | 責めず、次の道を3つ渡す |
| Empty | Journal `.j-empty` | 一文+別の行き先 |
| JS なし | Products の `<noscript>` | 一文+直接開けるリンク |
| Loading | なし(静的) | `aspect-ratio` と `--bg-3` で領域を確保。スピナーは作らない |
| Success | なし(フォームなし) | フォームを持つときに §6 で決める |

## 5. Product Design Systems(Level 3)

- 憲法とは別の系を認められているのは **clinic-flow-3d だけ**(2026-09-12 社長発効・全文は context.md 冒頭)。基準は `clinic-flow-3d/docs/ux-audit-v85.md` §4、アイコンは線画 SVG(`clinic-flow-3d/app/ui/icons.js`)。ブランドサイトの見た目へ戻さない。守る条は発効文どおり: 第8条・第15条・第19条3〜4号・44px/AA・スマホ最優先・文字量を抑える・三分法。
- プロダクト紹介 LP 系(`shared/subpage.css` を読む9ページ)はブランドサイトの一部として第22〜24条の下にある(同じ4系統を別名で持つ。`--paper`=`--bg`、`--serif-jp`=`--mincho` など。B-4)。その他のアプリに第22〜24条がどう及ぶかは未決事項 #8。
- プロダクト一般に別の系を認めるかは未決事項 #8。designer は判断材料(なぜブランドの系では足りないか)を揃えて社長に上げる。

## 6. 増やすときの規則

新しい Component / token / pattern は、次を**すべて満たすときだけ**足す。判断は designer。

1. 既存の部品(§3)・型(§4)では表せない
2. 使う場所の2か所目が実際に現れている
3. 交差・余白・選択の瞬間で説明できる
4. ひとり運営の保守に見合う

- 一度しか使わないものは、そのページの `<style>` に置く。共通へ昇格させない(第14条の UI 版)。
- 同じ UI が3か所以上で独自に実装されていたら共通化を検討する。見た目を変えずに1か所ずつ。
- トークンは役割の名前で足す(色名にしない)。色数が増えないかを第22条で照合する。
- 使われなくなった部品・トークンは、全ディレクトリで未使用を確かめてから消す。
- 憲法に触れる判断は designer が決めない。PM・auditor 経由で社長へ(第33条)。
- UI 変更の流れは CLAUDE.md のとおり(憲法 → 本書 → 既存の部品・トークン確認 → designer → 実装 → qa → pm → 社長)。
