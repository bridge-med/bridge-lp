### Radius と Shadow

**角丸を使うことと、カードにすることは別の判断である**(第24条・context.md §7)。角と影は対で使う。

| 段 | 値 | 影 | 意味 | 実体 |

Soft を多用しない(第24条)ので、新しい部品はまず Edge で考える。新しい半径・新しい影を足さない。

### Motion

動きは構図・主役・現在地の変化を伝えるために使う。派手にするためには使わない。

- 登場は `[data-reveal]`(1s・`data-reveal-delay` 1〜4)。hover は浮上 2〜4px・縁の色・矢印(.2〜.35s)。緩急は `--ease` の1本。
- `prefers-reduced-motion` では完成した姿を最初から見せる(共通 CSS で処理済み。ページ独自の動きも同じ扱い)。JS なしで中身が透明のまま残らないこと。
- 下層ヒーロー(`.page-hero`)の動きは、読み込み時に一度、見出しの下の線を左から引くだけ(`transform:scaleX` 約1秒)。砂の点は線が通った後に opacity だけで出る。既定値は完成形で、keyframes の from 側だけで動かす。ヒーローのパンくず・見出し・リードに `[data-reveal]` を付けない(見出しは最初からある)。ループ・スクロール連動・章ごとの線描きはしない(2026-10-04)。
- 常時ループはトップのヒーローの Experience Journey だけ(2026-10-04)。一本の線とカメラの移動で約 16.6 秒で一周し、継ぎ目は視点の移動と線の巻き戻しで渡す(場面をフェードで入れ替えない)。要素に許す動きは「線が伸びる/語が線から出る/点が線を進む/数値が入れ替わる」の4つで、移動と拡大はカメラの仕事。一時停止ボタン(44px・`aria-pressed`。WCAG 2.2.2。部品は §3 の `.motion-toggle`)を必ず置き、画面外・非表示タブでは止める。`filter` のぼかしは使わない。動きを減らす設定では俯瞰の静止の1枚(世界の中にロゴを含めない。BRIDGE は h1 のロックアップのまま上に置く)。ロゴの登場は読み込み時に一度、マークの二本の線を描くだけ(dashoffset のみ。名前は最初からある。光・回転・字間の動きを足さない)。藍の先端がそのまま Journey の線になり、ループではブランドの導入を繰り返さない。表現の約束の細部は `index.html` の `<style>` 冒頭に置く(使う場所が1か所なので §4 に上げない)。他ページに足すときは §6。
- スクロールに従う動きは、トップの #about の閉じ(`.kz`)だけ(2026-10-05・社長決裁。PR #144)。時刻はスクロール位置だけで決まり、固定・吸着・スクロール量の書き換えをしない。止まっているあいだは描かない。常時ループではないので一時停止ボタンは置かない。動きを減らす設定と JS がないときは完成形(マークだけ/帯ごと出さない)。細部は `index.html` の『閉じの約束』。他のページに足すときは §6。

## 4. Patterns

- **Page opening** — 下層は `.page-hero` 一つ(パンくず → h1(下を線が通り、書き出しの真下に砂の点) → リード1〜2文)。トップのヒーロー(BRIDGE のロックアップ → Experience Journey → 短い説明と CTA の帯)は他ページへ複製しない。
- **Content hierarchy** — 1画面に主役1つ。1セクション=見出し1つ+本体1つ。説明を足す前に削れる文を探す。カードのグリッドは1ページ1か所まで。
- **Choice** — 基本形は Where to next の3分岐。3つは関わり方の違うもの(読む/話す/使う)にする(第27条)。
- **Navigation** — 地図は `NAV` 配列から自動で揃う。404・空の状態も含めて行き止まりを作らない(第26条)。
- **CTA** — 主ボタン1つ+ghost か文字リンク+`.walk-note`「何もしなくても十分」(第29条)。急かす言葉・残数・カウントダウンを置かない。トップのヒーローだけ、主ボタンは Journey の分岐が見えた頃に一度出て、以後は消えない。それまでの入口はナビの文字リンクで、最初から使える。止めたとき・画面外・動きを減らす設定・JS なしでは待たせない。他ページで主ボタンを遅らせない。
- **道のり** — 横一列の点、最後の点だけ砂、860〜900px で縦に畳む。4ページに重複あり(B-2)。新しく使うときは写さず、共通化してから使う。
- **映像** — ページに結線する映像は `.reel`(§3)で置く。一度だけ・無音・ループなし。画面に半分入ったら再生し、画面外・非表示タブで止めて戻ったら続きから。人が止めたら再開しない。停止ボタン(`.motion-toggle`)を必ず置く。動きを減らす設定では静止画(ポスター)と再生ボタン。版はテーマ × 画角(`{light,dark}-{wide,tall}`。760px 以下は 4:5)の4本から1本だけを、近づいてから読む。1ページ2本まで。2本が同時に画面に入らない(窓の下端から次の窓の上端まで1画面以上)。同時に再生するのは1本だけ(`bridge.js` が止める)。finale(ロゴへの受け渡し)は1ページ1本。書き出しの規律(写し・動きのぼけ・地)は映像ごとのもので、§7 B-13 の記録に従う(designer 2026-10-09)。
- **状態**

| 状態 | 現状 | 標準 |
|---|---|---|
| Error | `404.html`(点線の二本線・一文・3つの出口) | 責めず、次の道を3つ渡す |
| Empty | Journal `.j-empty` | 一文+別の行き先 |
| JS なし | Products の `<noscript>` | 一文+直接開けるリンク |
| Loading | なし(静的) | `aspect-ratio` と `--bg-3` で領域を確保。スピナーは作らない |
| Success | なし(フォームなし) | フォームを持つときに §6 で決める |

## 6. 増やすときの規則

新しい Component / token / pattern は、次を**すべて満たすときだけ**足す。判断は designer。

1. 既存の部品(§3)・型(§4)では表せない
2. 使う場所の2か所目が実際に現れている
3. 交差・余白・選択の瞬間で説明できる
4. ひとり運営の保守に見合う

- 一度しか使わないものは、そのページの `<style>` に置く。共通へ昇格させない(第14条の UI 版)。
- 同じ UI が3か所以上で独自に実装されていたら共通化を検討する。見た目を変えずに1か所ずつ。
- トークンは役割の名前で足す(色名にしない)。色数が増えないかを第22条で照合する。
- 使われなくなった部品・トークンは、全ディレクトリで未使用を確かめてから消す。
- 憲法に触れる判断は designer が決めない。PM・auditor 経由で社長へ(第33条)。
- UI 変更の流れは CLAUDE.md のとおり(憲法 → 本書 → 既存の部品・トークン確認 → designer → 実装 → qa → pm → 社長)。
