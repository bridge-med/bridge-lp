2026-10-25・情報設計の担当(BRIEF §11.5)。`docs/ia.md` v3.3 を土台にした提案。本番のページ・`shared/`・`docs/` は変えていない。
画面は 2026-10-25 にローカルで撮った本番と試作 `hiraku3`(撮影の時点。WebGL なし=止めた町)。試作は並行して直されているので、事実は読んだ時点のもの。ひらいた状態だけ `hiraku2` の最終画面。撮った全画面(PC 1440×900・スマホ 390×844、最初の画面とページ全体・末尾・フッター・メニュー)は現場の作業領域(scratchpad の `ad-hiraku3/ia/shots/`)に置き、リポジトリには入れていない。

- **下層に直接来た人:** ロゴ・パンくずの Home・フッターの「町を歩く」→ 町。Products の「町で見る」→ その建物がひらいた町(`#town/hospital`)

## b. トップ(町)と Products の線引き

町は「出会う」(場所で、ひとつずつ)。Products は「選ぶ」(全部を並べて、比べて、絞る)。

| | トップ(町) | Products |
|---|---|---|
| 問い | どこから歩く? | 何が使える? |
| 並べ方 | 建物(場所) | 用途の節(同じ6つ・同じ語) |
| 道具の情報 | パネルで1つずつ(写し1枚・名前・一行・誰向け・利用条件・行き先の種類・ボタン。BRIEF §11.1) | 全行に名前・一行・誰向け・利用条件・ボタン |
| 探し方 | ふれる・前/次・広場の見晴らし | 検索窓・用途のチップ・ハッシュ |
| 迷った人へ | 最初の画面の Compass | 初めてなら、この3つ |
| 持たないもの | 検索・チップ・全件の比較 | 町の絵・建物の名前 |

- **町の案内(下の節)は町の凡例。** JS・WebGL がなくても29点に届く保証(BRIEF 9.7)。名前と一行にとどめ、誰向け・利用条件・検索は足さない(足せば Products の写しになる)。並びは町の順のままでよい(語と数が同じなので迷わない)
- **行き来は2本だけ。** 町の案内の帯とパネルの末尾に「この用途を一覧で比べる(n点)」→ `products/index.html#work` など。Products の節の見出しに「トップの町で見る(病院)」→ `index.html#town/hospital`
- **データは PRODUCTS が唯一の情報源。** 町の TOOLS はいま写しなので、本番化までは check-site で照合し、本番化で PRODUCTS から作る(f)

| 部品 | 役割 | トップ(町) | 下層 |

| メニュー | 全ページの地図(8つと一言) | NAV と同じ8つと一言。先頭に「町の案内(このページの下)」 | 変えない |

- 見た目(書体・色・昼夜)は町のもの。行き先・順・語は共通で、`bridge.js` の NAV から描く(唯一の情報源のまま)

- 下層のヘッダーに町への入口は足さない。ロゴとパンくずの Home が町へ行く。トップの都合で下層の部品を増やさない

## d. 町から通常のページへの接点

見た目は寄せない。言葉・行き先・線(ロゴ)の3つでつなぐ。町の絵は町の外へ持ち出さない。

| 接点 | どこ | なぜ違和感がないか |
|---|---|---|
| 1 パネルが前室 | 町のパネル | 町 → 生成りの紙のパネル → 紙のページと、少しずつ通常のページに近づく。文言は PRODUCTS と各ページの語のまま |
| 2 同じ一文 | 広場・町の閉じ → Philosophy の冒頭 | 「正解を与えるのではなく、選択肢を増やす」が両端にある。町の側を明朝にそろえれば(第23条 v1.5)、書体ごと同じ一文で迎えられる |
| 3 名前の由来 | 広場 → About の名前の由来 | 広場の二本の弧 = ロゴ = About の「交差」の映像。同じ形を、町では立体、About では線で見る |
| 4 人 | アトリエ → About `#founder` | アトリエの机の一人から、本人のポートレートへ。比喩から本人に移る |
| 5 同じ用途の語 | 建物の一行 ↔ Products の節の題 | 「明日の業務を楽にする」が両方の見出し。着くとチップが選ばれている |
| 6 戻ると同じ状態 | 町の URL `#town/hospital/keiji` | 戻るボタンで同じ建物・同じ道具に戻る。「町で見る」でもその建物がひらく(第27条: 選択に世界が応答する) |
| 7 共通のフッター | 町の閉じの下と全ページ | 町の最後が、どのページにもある同じ地図で終わる。その先は通常のページ |
| 8 「町を歩く」1行 | 下層のフッター | 検索で下層に直接来た人が町を知る入口。絵ではなく文字 |
| 9 任意: 一文が移る | 広場のパネル → Philosophy | 文書をまたぐビュー遷移で、同じ一文が冒頭へ移る。対応しないブラウザは普通に移る。designer の判断 |

やらないこと:
- 下層の書体・色・ヘッダーを町に寄せない(第30条の2 と同じ考え方。つなぐのは体験と言葉)
- Philosophy に広場の絵、About にアトリエの絵を置かない。町の色は第22条の外で、認めるならトップに限る但し書きになる。About には本人のポートレートがある
- フッターに小さな町の地図(絵)を置かない。文字の地図と二重になり、全ページに町の色が出る。代わりに「町を歩く」1行
- Products の行ごとの「町で見る」は置かない。29本の同じ顔の分岐(第27条)。行の主役は実物を開くこと
- Stories を病院のパネルに入れない。パネルは道具(使う)の入口で、読むものを混ぜると役割がぼける

## 社長の判断が要ること

3. ヘッダーの語: NAV.en(下層と同じ。推奨)か、日本語にして全ページを同時に変えるか
4. Research をフッター(推奨)とメニューに入れるか
5. アトリエの3つめを note から手記(Journal)に(推奨)
6. 事務所のパネルに Services への1行(biz と)
7. スマホの最初の画面に一覧への文字リンクを置かない(推奨)
