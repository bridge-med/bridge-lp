5. 見直し

  • designer(アートディレクター): 推しは案A。最初のスクロールで「まだこの世界が続いている」と感じさせるのは案A、第2画面の一枚の絵としての完成度は案B が上、という見立て。案A の終わり方に案B の一枚の絵の質を入れることを条件にした(病院ぜんたいで止めて札と灯りで階を降りる・屋根を残す・見下ろす角を下げる・倒れた壁を広場の下へ沈める・札を物の真上に・止めた画像の二重写しをなくす)。案B には、建物を約1.2倍・夜の土と側壁・入り方・切り口・札の文字。2回目の直しですべて反映し、現場が測った(上の各案の数字)。直した後の画面は、designer はまだ見ていない
  • editor(編集長): 一文を「いつもの仕事のそばに、道具を置いています。」に(「置いてみました」の守りの言い方と、「3つの」という品揃えの前置きを外す)。下のリンクは「明日の業務に使える道具を見る」(本番のトップと同じ語で、着いた先の見出しとも合う)。階の札は「3F 休憩室」「2F ナースステーション」「1F 受付」(部屋の名前でそろえる)。すべて反映。保留は掲示じたくの場所(6の②)
  • qa(品質管理): リンク切れ・横のはみ出し・コンソールのエラーは0。最初の画面は v4 と同じ。直す8点(見えないまま Tab が止まる所・読み上げに届かない一文・途中からの再読み込み・背の高い画面の下の紙の帯・背の低い画面で消える見出し・JS なしの並び・夜に昼の画像を先に読む・PC の昼のナビのコントラスト)は現場が直し、同じ検査で確かめた。qa の再実行はしていない(本番へ進むときに再実行する)
  • pm(右腕): 判定は held(試作として見せてよい)。本番には出していない(検索に載せない設定で、どこからもつないでいない)。病院の3つの道具の名前・一行・行き先は、道具の一覧と一致。見せ方の条件3つ(実物を開ける形・動く所の一行・推奨の横の但し書き)は、このページに入れた。PM の追加の指摘2点(案A: スマホのブラウザの帯が畳まれたとき、舞台の下に紙の色が覗くおそれ / 案B: 町が立体になる前にスクロールすると、二つめの立体を場面の替わり目で作り始める)も直した

6. 社長に決めていただくこと

  • ① 方向。推奨は案A(designer・PM とも)。案A は同じ絵のままカメラが寄るので、作りそのもので「まだこの世界が続いている」を満たす。案B も同じ空と光で続くが、町の島と病院の一切れの間で絵が替わり、0.5画面の位置では最初の画面の入口のボタンがその間に挟まる
  • 案A の弱み: 着いてから約1画面はカメラが止まり、札と一行と灯りだけが階ごとに替わるので、止まって見えるおそれがある。指の動きに結びついた動きなので、引っかかりもそのまま見える。案B の強み: ふつうのスクロールのまま、3つの階と道具を一枚の絵で一度に読める。止めた画像だけでも成り立つので、重いときの逃げ道がある
  • 案A を採ることは、町の場面に限って、画面に固定した舞台・スクロールで動くカメラ・物が見えてから出る札を認めることでもある(舞台の固定は以前の改訂で外した動き。札の出し方は 2026-10-11 の指示「演出に内容の可視性を依存させない」の字面から外れる)。案B なら、画面に入ると壁が沈む動き(v4 で外した種類)と二つめの立体を認めることになる
  • 条件: 社長の iPhone と Android の中位機で、寄る間に引っかからず、舞台の下が覗かないこと。だめなら案B の一枚の絵へ寄せる(案A は、動かないときにひらいた病院の止めた画像へ替える作りをすでに持つので、寄せる手間は小さい)
  • この推奨の但し書き: designer の推しは第1回の時点のもので、直した後の画面は見ていない。重さの数字はソフトウェア描画での推定で、実機では測っていない
  • ② 掲示じたくの場所。推奨は 1F 受付(待合の掲示)へ移し、二度手間さがしを 2F へ。掲示じたくの対象は「受付・事務の方に」で、作る掲示は外来向け。いまの 2F ナースステーションでは「ナースステーションで院内掲示をつくる」と読める。2案に共通なので、直すのは方向が決まってから
  • 今回は伺わないもの: v4 から持ち越しの判断(最初の画面のボタンの言葉、見出し「病院の外にも」、規定の改定、昼夕夜とダーク)。下の幕を作るときにまとめる

7. 重さ・アクセシビリティ

393×724・画素比2・CPU 等倍・各1回。Chromium のソフトウェア描画での値です。iPhone の実機の GPU と Safari では測っていないので、推定として見てください。

  • 立体に替わるまで: v4 4.4秒、案A 4.1秒、案B 4.7秒(それまでに読む量は 案A 1,954KB・案B 1,953KB・v4 2,178KB)
  • 案B: 二つめの立体の最初の描画で長いタスク 2.4秒(CPU を4倍遅くすると 3.3〜4.9秒)。町が立体に替わったあと、手の空いたときに作る。それまでは止めた断面の画像
  • 案A: CPU を4倍遅くすると、舞台を進む間に長いタスク 25件(最大 345ms。等倍では1件)。3D をスクロールに合わせて毎こま描くため
  • 画面のずれ(CLS): 案A 0.0055〜0.0065、案B 0.0003〜0.0014(v4 0.0005)
  • 動きを減らす設定・WebGL なし: 案A は町の止めた画像を病院へ寄せてから(動きを減らす設定では寄せない)、ひらいた病院の止めた画像へ 0.25秒で替える。案B は止めた断面と札。JS なしでは、2案とも道具の一覧(29件)に届く
  • キーボードと読み上げ: 帯 → 町の建物 → 道具の札 → 一覧へ → 終わり → フッターの順。案A は Tab で舞台が各階まで進み、札が見える所に出る。「病院の中」と一文は、2案とも読み上げに届く
  • 未確認: 実機(iPhone の Safari・Android の Chrome)、VoiceOver と TalkBack の実際の読み、ブラウザの帯が畳まれて画面が伸びるとき(案A の舞台の地は、その時刻の空の下の色にした)
